## 1. Purpose and guardrails

This plan breaks the RED findings into ordered GREEN slices. Continue on the existing relevant branch/PR and avoid parallel branches or PRs for the same work. Do not create a new PR merely to split a dependent slice. Each slice must run through GitHub Actions against its exact source SHA and be reviewed before dependent work proceeds.

This document does not modify production code and does not authorize Feeder startup, canonical database initialization, exchange connectivity, migration execution, deployment, or live execution.

Non-negotiable constraints:

- One canonical T0 candle writer authority.
- T0 canonical data and Paper persistence use distinct physical SQLite databases.
- No shared live SQLite writer between PC and Android; one writer authority only.
- Missing or ambiguous storage configuration fails closed.
- No implicit schema writes from constructors or read APIs.
- PostgreSQL cannot be canonical until equivalent fencing and acceptance evidence exist.
- Kraken Spot remains isolated from canonical Futures data.
- Paper Gate protects every Paper mutation and schema write.
- Tests use temporary isolated databases and synthetic fixtures only.
- Every slice has a GitHub Actions run against its exact source SHA.

## 3. Implementation slices

### G0 — Freeze contracts and isolated test harness

**Scope**
- Freeze Gateway and Paper Gate interfaces, state machines, failure semantics and storage-path rules.
- Provide test-only temporary DB factories and deterministic clocks/process coordination helpers.
- Define GitHub Actions workflow stages and artifact naming; do not weaken or skip existing RED assertions.

**Acceptance**
- Contract tests describe observable behavior, including fail-closed cases.
- Tests cannot resolve or open production/canonical paths.
- No production runtime behavior changes in this slice.

**GitHub Actions**
- Contract tests, workflow syntax/validation, compile/import checks.
- Verify the test harness rejects non-temporary DB paths.

### G1 — T0 Gateway primitive

**Scope**
- Add the single Gateway API for canonical candle writes.
- Gateway owns validation and write transaction boundary.
- Validate lease name, owner, generation and expiry in the same transaction that commits the candle batch.
- Atomic batch semantics: all rows commit or none.
- Do not yet remove old writer paths in this slice unless required to keep tests safe; mark them as forbidden and cover with tests.

**Acceptance**
- Valid lease accepted.
- Expired, wrong owner, stale generation and missing lease rejected.
- Lease takeover race cannot allow stale writer commit.
- Batch failure rolls back the entire batch.
- No network/exchange dependency.

**GitHub Actions**
- Gateway unit + SQLite concurrency tests.
- Compile/import checks.
- Persist test logs and source SHA.

### G2 — Route T0 candle writes through Gateway

**Scope**
- Make `sync_window()` require Gateway/fence; remove optional unfenced fallback.
- Make CLI call the same mandatory fenced path.
- Remove startup `insert([])` schema side effect; introduce explicit, separately authorized schema initialization.
- Remove or hard-fail direct production `CandleStore.insert()` and facade bypasses.
- Ensure API/factory construction is side-effect-free.
- Keep PostgreSQL canonical writes disabled; do not add a parallel writer.

**Acceptance**
- Direct insert, storage facade, CLI, feeder startup and missing-fence calls cannot mutate canonical candles.
- Gateway is the only canonical candle commit path.
- Existing read APIs remain compatible and read-only.

**GitHub Actions**
- T0 gateway bypass suite.
- sync/CLI integration tests with temporary SQLite.
- Schema lifecycle and regression tests.
- Compile and existing T0 integrity suite.

### G3 — T0 process lifecycle and recovery acceptance

**Scope**
- Exercise lease acquire/heartbeat/release, expiry, process interruption and restart against Gateway.
- Verify status publication is separately scoped and cannot mutate candles.
- Validate recovery and stale-generation invalidation.

**Acceptance**
- Concurrent writer/takeover tests are deterministic.
- Stale process cannot commit after takeover/restart.
- Recovery never bypasses Gateway.
- No production DB is touched.

**GitHub Actions**
- Multiprocess tests, forced interruption tests and repeated concurrency runs.
- T0 integrity + compile.

### P1 — Paper Writer Gate primitive

**Scope**
- Implement Gate state machine: OPEN, DRAINING, DRAINED.
- Implement writer admission, generation-bound token, idempotent release, drain wait and guarded reopen.
- Timeout and invalid state fail closed.
- Gate storage/coordination must be process-safe; do not rely only on an in-process mutex if multiple processes can write.

**Acceptance**
- DRAINING rejects new writers.
- DRAINED is reached only with zero admitted writers.
- Timeout does not report DRAINED.
- Stale-generation token rejected; double release is safe and idempotent.
- Restart invalidates prior generation tokens.

**GitHub Actions**
- Gate state-machine tests.
- Multiprocess admission/drain race tests.
- Timeout and crash/restart tests.

### P2 — Paper DB isolation and explicit schema lifecycle

**Scope**
- Require explicit `PAPER_DB`; remove PaperLedger's implicit MARKET_DATA_DB fallback.
- Resolve and compare canonicalized filesystem identity, including symlink aliases, before opening DB.
- Fail closed if PAPER_DB is absent, aliases T0 canonical DB, or Gate is not OPEN/admitted.
- Separate schema initialization from constructors and read paths.
- Keep test DB factories restricted to temporary paths.

**Acceptance**
- Missing PAPER_DB fails before file creation/open.
- Same path and symlink alias to T0 fail before file creation/open.
- Constructor/read-only calls do not create tables or mutate state.
- Explicit schema initialization requires Gate admission.

**GitHub Actions**
- Path identity tests across relative/absolute paths and symlinks.
- No-file-created assertions for all rejection paths.
- Schema lifecycle and compile tests.

### P3 — Integrate all Paper mutators

**Scope**
- Gate every Ledger write: submit, fill/order updates, cancel, audit, state, pause/kill and strategy state.
- Gate Equity writes: history, account config, daily baseline and initialization.
- Gate Risk Control writes: kill, reset, pause and initialization.
- Ensure every admission token is released in a finally-safe path.
- Keep reads separate from write services.

**Acceptance**
- Every mutation rejects when Gate is DRAINING/DRAINED.
- No mutation opens or creates DB before admission.
- Failed writes roll back and release writer admission.
- Existing Paper semantics and accounting invariants remain unchanged.

**GitHub Actions**
- Per-module writer-gate tests.
- Ledger/equity/risk regression tests.
- Fault injection for exceptions between admission and commit/release.
- Compile and full Paper unit suite.

### P4 — Pipeline API, budget and read-only semantics

**Scope**
- Move `paper_control_budget` to PAPER_DB and protect writes with Gate.
- Ensure `equity_snapshot()` does not persist equity; move persistence to an explicitly named admitted write operation.
- Make health/status/equity/audit read endpoints truly read-only.
- Verify pipeline construction and readiness checks have no DDL/DML side effects.

**Acceptance**
- Budget writes only to PAPER_DB under Gate.
- Read endpoints cause zero DB file/schema/row changes.
- Corrupt/stale state remains a service error; do not silently repair during reads.
- Kill switch and control-token behavior remain fail-closed.

**GitHub Actions**
- Pipeline API integration tests with separate temporary T0/Paper DBs.
- Before/after DB fingerprint assertions for read endpoints.
- Control permit isolation and kill-switch regression tests.

### P5 — Migration, drain, restart and recovery integration

**Scope**
- Migration admission requires no active T0 Feeder lease and Paper Gate DRAINED.
- Ensure migration has explicit authorization and separate audit evidence.
- Validate rollback, schema fingerprint, row counts, sequence state and integrity.
- Verify restart/recovery preserves fail-closed behavior and invalidates stale writer tokens.

**Acceptance**
- Migration refuses while Feeder lease exists or Paper writers remain active.
- Drain timeout blocks migration.
- Failure rolls back without partial target state.
- Recovery does not silently reopen writers or start Feeder.

**GitHub Actions**
- Migration block/allow tests on disposable DBs.
- Rollback and integrity tests.
- Restart and stale-token tests.

### G-final — Integrated acceptance and RED-to-GREEN decision

**Scope**
- Run the full T0 Gateway + Paper Gate + pipeline + migration suite on one exact commit.
- Re-run complete writer/mutator scan and classify any new candidates.
- Review all diffs and GitHub Actions artifacts.

**Acceptance**
- All mandatory suites pass; no skipped test may conceal a required contract.
- Compile succeeds.
- No unfenced production T0 writer remains.
- No ungated Paper writer or implicit schema writer remains.
- Read-only endpoints show no writes.
- T0 and Paper DB path isolation verified.
- PostgreSQL canonical writer remains disabled unless a separate equivalent-fencing project passes.
- Live execution remains disabled.

**Decision**
- Only after evidence review may G2 status be proposed for change.
- GREEN does not mean live trading authorization.

## 4. GitHub Actions execution protocol for every slice

For each slice:

1. Continue on the existing active branch/PR where possible; do not create parallel branches or PRs for the same work.
2. Add or update tests before/with the implementation; do not weaken existing assertions to obtain a pass.
3. Run the named GitHub Actions workflow on the exact source SHA. Use Codemagic only if GitHub Actions is blocked or cannot execute.
4. Capture workflow ID, commit SHA, workflow name, status, test counts and artifact checksums.
5. If any test fails, stop the dependent sequence and investigate; do not begin the next slice.
6. Review the diff for correctness, architecture, security and scope.
7. Keep the existing PR open and unmerged. Do not create a duplicate PR or merge automatically.
8. Continue only after the user approves the slice and its evidence.

A failed or unavailable GitHub Actions run is not a pass. Local tests do not replace the required GitHub Actions evidence. A Codemagic fallback must still identify the exact source SHA and artifact.

## 5. Stop conditions

Stop the sequence immediately if:

- A test attempts to access a non-temporary/canonical database.
- A rejected writer creates or opens a DB file.
- Lease validation and candle commit are not atomic.
- Gate reports DRAINED while any writer is active.
- A Paper mutation occurs without a valid current-generation token.
- A read endpoint performs DDL/DML.
- A migration proceeds while a Feeder lease or Paper writer is active.
- Any live order or exchange execution path is enabled or invoked.
- GitHub Actions result does not correspond to the exact reviewed commit SHA.
