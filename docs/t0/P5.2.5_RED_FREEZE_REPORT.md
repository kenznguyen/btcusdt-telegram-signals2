They identify missing contracts in the reviewed source; they do not prove runtime concurrency, transaction isolation, crash recovery, process isolation, or filesystem permissions.

## 4. Frozen contract-gap baseline for GREEN

### SWG-A — Single canonical write gateway
- Introduce one canonical write gateway as the only supported T0 candle-data write entry point.
- Close or reject public unfenced writer APIs, including legacy `CandleStore.insert()`.
- Make canonical sync require explicit gateway authority.
- Prevent CLI/manual paths from bypassing the gateway.

### SWG-B — Lease fencing
- Validate Lease owner, generation/epoch, and expiry inside the same SQLite write transaction as the protected data mutation.
- Reject stale owner/generation and expired Lease contexts.
- Ensure takeover cannot permit an old writer to commit after the new generation is authoritative.

### SWG-C — Atomic batch write
- Gateway owns the batch transaction.
- A failed batch must roll back completely; no partial data publication.
- Retry/idempotency semantics must be explicit and tested.

### SWG-D — Read-only consumers
- Consumers must open canonical data read-only.
- No consumer may obtain write authority through a read API.
- The passing static assertion is limited to the checked connection contract; process and filesystem isolation remain to be demonstrated.

### SWG-E — Close alternate T0 write paths
- Sync CLI and recovery must route only through the gateway.
- PostgreSQL must be explicitly denied as a canonical writer until equivalent fencing is implemented and verified.
- Repository-wide writer inventory must be maintained; every writer path must be classified and either routed through the gateway or prohibited.

### SWG-F — Paper writer isolation
- Paper DB has its own writer admission gate, independent of T0 Lease.
- Required state progression: `OPEN → DRAINING → DRAINED → REOPEN`.
- Drain closes admission before waiting; `DRAINED` requires zero in-flight writers.
- Timeout fails closed and must not grant migration permission.
- Stale-generation tokens cannot commit or alter the current generation's in-flight count.
- Release must be idempotent and must not underflow the in-flight count.
- Reopen requires a settled migration outcome and zero in-flight writers, then advances the generation.
- Paper writer authority must never authorize T0 writes.
- Every PaperLedger mutation path must participate in writer admission.

## 5. GREEN acceptance gates — not yet satisfied

GREEN implementation and acceptance must remain blocked until all of the following are addressed and tested:

1. Complete source inventory of every T0 and Paper writer, including scripts, CLI, recovery, maintenance, direct SQL, and indirect callbacks.
2. No public or reachable unfenced canonical writer remains.
3. Lease validation and protected T0 mutation are atomic in the same transaction.
4. Single Writer Gateway is the only canonical write boundary; process/filesystem permissions prevent other processes from writing the canonical DB.
5. All canonical consumers use an explicit read-only contract and a defined generation/snapshot resolver before atomic migration is attempted.
6. PaperLedger and all Paper write helpers use the Paper writer gate.
7. Runtime tests cover concurrent writers, drain races, stale tokens, timeout, rollback, crash/restart, duplicate release, retry/idempotency, and reopen.
8. Codemagic Shadow workflows pass the GREEN contract suite with source SHA and artifact identity recorded.
9. No canonical DB, production Feeder, exchange connection, or live order path is involved in GREEN Shadow tests.

Static source checks alone are insufficient evidence for runtime safety.
