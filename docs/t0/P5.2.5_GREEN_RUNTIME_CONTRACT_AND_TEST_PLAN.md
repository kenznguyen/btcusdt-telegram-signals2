## Database identity and ownership contract

- `MARKET_DATA_DB` is reserved for T0 canonical candles and T0 operational metadata only.
- `PAPER_DB` is mandatory for PaperLedger, risk state, equity history, audit, paper orders and paper_control_budget.
- No fallback from missing `PAPER_DB` to `MARKET_DATA_DB`; missing PAPER_DB fails closed.
- At startup, resolve both paths and reject equality after canonical path resolution (including symlink/relative-path aliases).
- All Paper API callsites must use PAPER_DB: ledger(), control_permit(), core_decide() read_snapshot, /v1/paper, /v1/audit, equity recording and all POST control routes.
- T0 API/feeder/CI continue to use MARKET_DATA_DB only.
- Kraken Spot must use a separately configured path and reject equality with MARKET_DATA_DB and PAPER_DB.
- A PaperWriterGate token can authorize only Paper DB mutations; it is never accepted by T0WriteGateway. T0 lease cannot authorize Paper writes.
- Test path isolation using two distinct temporary files; prove T0 candle tables exist only in T0 DB and all Paper tables exist only in PAPER_DB. Also prove aliases are rejected.

## T0 Single Writer Gateway contract

1. A single `T0WriteGateway` capability is the only application-facing canonical write authority.
2. The gateway accepts a validated batch and a lease capability; it does not accept a caller-supplied boolean or optional fence dictionary.
3. SQLite Lease owner, lease name, generation/fencing epoch and expiry are validated inside the same `BEGIN IMMEDIATE` transaction as candle mutations.
4. The entire batch commits or rolls back as one unit. Stale, missing, expired, wrong-owner or wrong-generation lease rejects the whole batch.
5. CLI, feeder, recovery and every ingestion path receive Gateway explicitly. Missing Gateway fails closed.
6. No application code may call CandleStore.insert, insert_fenced, adapter insert, or raw canonical write SQL directly.
7. PostgreSQL canonical writes remain disabled until an independently reviewed gateway adapter proves equivalent transaction fencing.
8. Reader construction/schema initialization must not create or mutate the canonical database outside an authorized maintenance operation.

## Paper Writer Gate contract

1. Independent `PaperWriterGate`, scope exactly `paper_only`; it cannot authorize T0.
2. State machine: OPEN -> DRAINING -> DRAINED. Admission closes before drain waits.
3. `admit_writer()` returns an opaque token bound to gate identity, generation and scope.
4. Every Paper mutation, including schema initialization, migrations, control budget, risk controls, audit and equity history, holds a valid token through transaction completion.
5. Token validation is enforced at commit. Old-generation, wrong-gate, wrong-scope, released or fabricated tokens cannot commit.
6. `release_writer()` is idempotent and cannot underflow active count.
7. Drain reaches DRAINED only at zero active writers. Bounded timeout remains fail-closed in DRAINING; no automatic reopen.
8. `reopen()` requires settled drain, zero active writers and explicit authorization.
9. Read-only snapshots remain available during drain and do not initialize schema or write.
10. Shared Risk Engine / Kill Switch checks remain inside the same PaperLedger transaction.

### Proposed process-safe gate architecture (design only)

The current runtime-test sketch uses in-process synchronization. That is insufficient for the P1 acceptance requirement because separate Python processes can each hold their own in-memory gate. The implementation must use a cross-process coordination primitive.

1. **Separate authority and storage**
   - `PaperWriterGate` has the fixed scope `paper_only`; it is not a T0 lease and cannot be passed to `T0WriteGateway`.
   - Use a small durable gate-coordinator SQLite sidecar associated with the explicitly configured `PAPER_DB`, plus a lock file. The coordinator stores gate identity, state, generation and active token IDs. It must not use `MARKET_DATA_DB`.
   - The gate coordinator and lock file are created only by an explicit initialization path after `PAPER_DB` path validation. A denied admission must not create/open the Paper data DB.
   - No third-party locking dependency is required. Use a platform adapter: POSIX file locks on Linux/Android; a Windows file-lock adapter for PC. If the platform lock cannot be acquired or its semantics cannot be verified, fail closed.

2. **Admission and token lifetime**
   - `admit_writer()` obtains the OS shared lock (exclusive on platforms whose adapter only supports exclusive locks), then checks the persisted coordinator state in a short transaction.
   - Only `OPEN` admits a writer. Admission records a random, opaque token ID bound to gate identity, `paper_only` scope and current generation.
   - The token retains its OS lock handle for the full Paper write transaction. It is not serializable or transferable to another process.
   - The gate validates gate identity, scope, generation and active token ID before mutation and immediately before commit. A token admitted before `DRAINING` may finish; a released, fabricated, foreign or stale-generation token cannot commit.
   - `release_writer()` removes the active token record before closing the OS lock. Releasing twice is a no-op and never decrements a count twice.

3. **Drain ordering and crash recovery**
   - `begin_drain()` first commits `DRAINING` in the separate coordinator DB, closing admission without waiting for the Paper DB write lock.
   - It then waits for the exclusive OS lock. Existing writers retain their lock handles through commit/rollback; admissions that race after the `DRAINING` commit see the closed state and release their handles without touching `PAPER_DB`.
   - After obtaining the exclusive lock, no writer process can still be active. The gate may clear orphaned token records left by a crashed process, verify zero in-flight writers, and commit `DRAINED`.
   - A bounded timeout leaves the state `DRAINING`; it must not claim `DRAINED`, reopen automatically, or authorize migration. A later explicit wait may complete the drain after writers exit.
   - OS lock release on process death is the recovery signal. A restart/drain test must prove that a killed writer cannot keep the gate permanently busy and that its old token cannot be reused after generation advancement.

4. **Reopen and migration boundary**
   - `reopen()` is allowed only from `DRAINED`, with zero active token records, explicit authorization and a settled outcome such as `ABORTED/NOT_STARTED`, `COMPLETED`, or `FAILED_ROLLED_BACK`.
   - Reopen increments the generation; all prior-generation tokens remain invalid.
   - A drain timeout is not permission to reopen. After the active writer exits, complete the drain, record the settled outcome, then explicitly reopen if authorized.
   - `DRAINED` is only a Paper-writer safety condition. It does not authorize a migration. Migration still requires separate explicit approval and independent verification that no T0 Feeder lease is active.

5. **Ledger and pipeline integration**
   - Make `PaperLedger` construction side-effect-free. Move DDL, initial rows and legacy-state setup into an explicit `initialize_schema()` operation that itself requires gate admission.
   - Wrap every mutator in one gate-owned transaction boundary: `submit`, `cancel`, `record_equity`, pause/kill/reset, strategy state, audit writes, equity history, risk-control updates and all schema initialization. Release admission in a `finally`-safe path after commit/rollback.
   - Keep `read_snapshot`, `read_audit`, equity snapshots and health/status reads strictly read-only. In particular, remove schema `ensure()` side effects from the equity snapshot path.
   - `control_permit()` must require the shared gate and explicit `paper_db_path`; all Paper reads/writes use `PAPER_DB`, never `MARKET_DATA_DB`. The runtime must inject one shared gate instance rather than constructing a new gate per request.
   - The gate token authorizes only Paper mutations. T0 writes continue to require the independent T0 Gateway and lease capability.

### Proposed public API and coordinator record model

The API below is a design target; names may be refined during implementation, but the guarantees must remain unchanged.

```python
class PaperWriterGate:
    @classmethod
    def initialize(cls, *, paper_db_path: str) -> "PaperWriterGate": ...
    def admit_writer(self) -> WriterToken: ...
    def validate_writer_token(self, token: WriterToken) -> None: ...
    def release_writer(self, token: WriterToken) -> bool: ...
    def begin_drain(self, *, timeout_seconds: float) -> DrainResult: ...
    def wait_for_drain(self, *, timeout_seconds: float) -> DrainResult: ...
    def reopen(self, *, authorized: bool, settled_outcome: str) -> None: ...

    @contextmanager
    def writer_transaction(self, *, paper_db_path: str):
        # admit -> open existing PAPER_DB read/write -> BEGIN IMMEDIATE
        # -> validate token -> yield connection -> validate -> COMMIT
        # -> rollback on exception -> release token in finally
        ...
```

- `WriterToken` is immutable, opaque, bound to `gate_id`, `generation`, `token_id` and `paper_only` scope. It carries a private OS lock handle and must not be serializable.
- Coordinator records: one singleton gate-state row (`gate_id`, `state`, `generation`, `updated_at_ms`) and one active-token row per admission (`token_id`, `gate_id`, `generation`, `scope`, `admitted_at_ms`). The active count is derived from token rows, not trusted as an independently mutable counter.
- Process ID is diagnostic metadata only; process liveness is not inferred from PID reuse. OS lock ownership is the liveness proof.
- `release_writer()` returns `False` for an already-released token and never decrements another generation.
- `begin_drain()` returns `DRAINED` only after exclusive lock acquisition and zero active token rows. Timeout raises/returns `DRAIN_TIMEOUT` while the persisted state remains `DRAINING`.
- `reopen()` requires a settled outcome enum (`ABORTED/NOT_STARTED`, `COMPLETED`, or `FAILED_ROLLED_BACK`) and increments generation atomically.
- `writer_transaction()` must open `PAPER_DB` with existing-file semantics (`mode=rw`); it must not create the file as a side effect of a denied or invalid admission. Schema creation is a separate explicitly admitted operation.
6. **Required P1 proof before implementation can be considered complete**
   - Multiprocess admission/drain race using separate processes, not only threads.
   - Prove `DRAINING` is persisted before drain waits and rejects all later admissions.
   - Hold a writer across drain; prove `DRAINED` only after the process releases its lock.
   - Kill a process while it holds a token; prove OS lock recovery, orphan-token cleanup and stale-token rejection.
   - Verify timeout remains `DRAINING`; verify explicit settlement is required before reopen.
   - Test POSIX/Linux (including Android-compatible semantics) and Windows lock adapters; unsupported behavior is fail-closed.
   - Test all Paper mutators and schema initialization against temporary isolated `PAPER_DB` only; verify reads cause no DDL/DML or file creation.

This is an architecture proposal for P1, not implementation approval. PR #112 now contains `paper_execution/test_writer_gate_runtime.py` with ten named process-level acceptance test cases. The production `paper_execution.writer_gate` module remains intentionally absent; the current RED run therefore stops each case at an explicit module-availability assertion. This proves test discovery and avoids import/test errors, but it does NOT execute multiprocess, crash-recovery, SQLite transaction or platform-lock behavior. Those behavior assertions remain NOT RUN until a separately authorized GREEN implementation exists. The timeout/reopen acceptance test requires a completed drain and explicit `ABORTED/NOT_STARTED`, `COMPLETED`, or `FAILED_ROLLED_BACK` settlement before reopen.

## Pipeline API writer contract

- `pipeline.api.control_permit(timestamp, *, writer_gate, paper_db_path)` is a Paper writer. It must acquire admission before opening the DB, perform BEGIN IMMEDIATE + budget mutation in PAPER_DB, commit, then release in finally. It must fail closed if admission is denied or transaction/commit fails. No SQL write may target MARKET_DATA_DB.
- `control_permit` must not create/open a Paper DB file when gate is DRAINING/DRAINED; denied admission produces zero filesystem/database mutation.
- `ledger()` must construct PaperLedger using PAPER_DB, never MARKET_DATA_DB.
- `core_decide()`, /v1/paper and /v1/audit are read-only Paper reads from PAPER_DB and must remain usable while gate is DRAINED.
- `equity_snapshot()` is currently a hidden writer because it calls record_equity(). Split it: dashboard snapshot is read-only; equity persistence is a separate admitted writer operation.
- Every POST route (pause/cancel/kill/reset/evaluate) and PaperLedger constructor/record_equity/mutators must use the same gate and hold admission through commit. No alternate gate instance per request if the runtime requires shared drain state.

## Runtime test requirements (all use TemporaryDirectory and synthetic data)

### Gateway
- Valid Lease batch commits; missing/expired/wrong owner/wrong generation rejects without mutation.
- Lease takeover races writer: old generation cannot commit after takeover.
- Prove Lease validation and candle mutation share one transaction.
- Inject failure on later candle and prove entire batch rollback.
- Identical replay idempotent; conflicting duplicate rolls back.
- CLI/feeder/recovery entrypoints fail closed without Gateway.
- Read-only consumer cannot write or initialize schema.
- PostgreSQL canonical write denied by default.

### Paper Gate / Ledger
- Concurrent admission/release accounting race-safe.
- Drain closes admission before waiting; DRAINED iff active count is zero.
- Timeout remains DRAINING and does not reopen.
- Stale generation, wrong gate, wrong scope, double release and underflow rejected.
- Reopen denied until drain settles and active count is zero.
- Parameterized over every mutating PaperLedger API, including constructor/schema init: no commit without admission; valid admission succeeds.
- Hold writer during drain; drain waits; after DRAINED no old token can commit.
- Read-only snapshot during drain does not create schema or write.
- Kill Switch and shared risk limits remain effective under concurrent submissions.
- Paper token cannot authorize T0; T0 lease cannot authorize Paper.

### Pipeline API / database isolation
- With gate OPEN, control_permit writes budget row to PAPER_DB and does not create/mutate any Paper table in MARKET_DATA_DB.
- With gate DRAINED, control_permit raises/rejects before opening/creating the DB; assert both DB files byte/schema state unchanged.
- During DRAINING with an admitted writer, drain waits until control_permit commits and releases; no new permit can enter.
- Force exception before commit and during commit: rollback leaves budget unchanged; token released exactly once.
- Missing PAPER_DB fails closed; MARKET_DATA_DB alone must never be accepted as Paper path.
- PAPER_DB == MARKET_DATA_DB, including symlink/relative alias, is rejected.
- ledger(), core_decide(), /v1/paper, /v1/audit all use PAPER_DB; test with decoy data in T0 DB to detect accidental reads.
- equity snapshot endpoint performs SELECT only; equity persistence uses admitted writer.
- All POST control routes are denied while DRAINED and leave orders, state, audit and risk-control rows unchanged.
