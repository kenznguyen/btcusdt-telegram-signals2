## T0 Single Writer Gateway contract

1. A single `T0WriteGateway` capability is the only application-facing canonical write authority.
2. The gateway accepts a validated batch and a lease capability; it does not accept a caller-supplied boolean or an optional fence dictionary.
3. SQLite Lease owner, lease name, generation/fencing epoch and expiry are validated inside the same `BEGIN IMMEDIATE` transaction as the candle mutations.
4. The entire batch commits or rolls back as one unit. Stale, missing, expired, wrong-owner or wrong-generation lease rejects the whole batch.
5. CLI, feeder, recovery and every ingestion path must receive the Gateway explicitly. Missing Gateway fails closed.
6. No application code may call `CandleStore.insert`, `insert_fenced`, adapter `insert`, or raw canonical write SQL directly.
7. PostgreSQL canonical writes remain disabled until an independently reviewed gateway adapter proves equivalent transaction fencing. Read-only PostgreSQL access may remain.
8. Read-only consumers use read-only connections/snapshots. Process and filesystem boundaries remain necessary because SQLite has no per-table ACL.

## Paper Writer Gate contract

1. Independent `PaperWriterGate`, scope exactly `paper_only`; it cannot authorize T0.
2. State machine: OPEN -> DRAINING -> DRAINED. Admission closes before drain waits.
3. `admit_writer()` returns an opaque token bound to gate identity, generation and scope.
4. Every mutating PaperLedger operation, including schema initialization and migrations, must hold a valid token through transaction completion.
5. Token validation is enforced at the commit boundary. Old-generation, wrong-gate, wrong-scope, released or fabricated tokens cannot commit.
6. `release_writer()` is idempotent and cannot underflow active count.
7. Drain reaches DRAINED only at zero active writers. Bounded timeout remains fail-closed in DRAINING; no automatic reopen.
8. `reopen()` requires settled drain, zero active writers and explicit authorization.
9. Read-only snapshots remain available while writes are drained and do not initialize schema.
10. Shared Risk Engine / Kill Switch checks remain inside the same PaperLedger transaction; writer admission does not bypass risk controls.

## Runtime test requirements (not static source assertions)

### Gateway
- Valid Lease can commit a batch; missing/expired/wrong owner/wrong generation cannot.
- Lease takeover races a writer: old generation cannot commit after takeover.
- Instrument transaction boundary to prove Lease validation and mutation share one transaction.
- Inject failure on a later candle and prove zero batch rows committed.
- Retry identical batch is idempotent; conflicting duplicate rolls back entire batch.
- All CLI/feeder/recovery entrypoints fail closed without Gateway.
- Read-only consumer cannot write.
- PostgreSQL canonical write is denied by default.

### Paper gate and ledger
- Concurrent admission/release accounting is race-safe.
- Drain closes admission before waiting; DRAINED iff active count is zero.
- Timeout stays DRAINING and does not reopen.
- Stale generation, wrong gate, wrong scope, double release and underflow are rejected.
- Reopen is denied until drain settles and active count is zero.
- Parameterized test over every mutating PaperLedger API: no commit without admission; valid admission succeeds.
- Hold writer during drain and prove drain waits; after DRAINED no prior token can commit.
- Read-only snapshot works during drain without creating schema.
- Gate identity/scope cannot be used as T0 Lease authority.
- Kill switch and shared risk limits remain effective under concurrent submissions.
