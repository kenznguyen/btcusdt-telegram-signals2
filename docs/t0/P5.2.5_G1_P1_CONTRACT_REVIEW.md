## 2. G1 — T0 Single Writer Gateway

### 2.1 Proposed boundary

Retain the frozen public operation:

```python
class T0WriteGateway:
    def insert_batch(self, candles, *, lease_token, now_ms) -> int: ...
```

Before implementation, specify these supporting contracts:

- `lease_token` is a typed capability issued by the T0 lease authority; callers must not be able to substitute a Paper Gate token or arbitrary owner/generation values.
- The Gateway and lease authority must refer to the same canonical SQLite database identity and transaction connection.
- The production clock is trusted/injected by the Gateway boundary. A caller-supplied `now_ms` is test-only or must be supplied by a trusted clock abstraction; an untrusted caller must not extend lease validity by choosing a timestamp.
- Lease validity is defined exactly: lease name matches; owner matches; generation matches; expiry is strictly later than the transaction's trusted current time.
- Lease validation and every candle mutation occur inside one `BEGIN IMMEDIATE` transaction on the same SQLite connection.
- No network calls, callbacks, sleeps or external work occur while the write transaction is held.

### 2.2 Batch and identity semantics

Freeze the following observable behavior:

1. Validate the complete batch before mutation; reject malformed timeframe, timestamp, OHLCV values and invalid OHLC relationships.
2. Define candle identity as the canonical key already used by the T0 schema (timeframe + open_time_ms, with symbol/market identity included if present in the schema).
3. An identical replay is idempotent and does not create duplicate rows.
4. The same identity with a different payload raises a typed conflict error; the entire batch rolls back.
5. Any invalid row, stale lease, SQL error or injected mid-batch failure rolls back all rows in that batch.
6. Empty batch behavior is explicit and side-effect-free; it must not initialize schema or touch WAL state.
7. Return value semantics are explicit (prefer count of newly inserted rows, not ambiguous attempted rows).

The implementation must preserve existing canonical candle semantics; this review does not authorize changing the schema or candle identity key.

### 2.3 Typed failure contract

Define stable exception classes/codes at minimum:

- `InvalidLeaseToken`
- `LeaseExpired`
- `LeaseGenerationMismatch`
- `LeaseOwnerMismatch`
- `InvalidCandle`
- `CandleIdentityConflict`
- `GatewayStorageError`

All failures are fail-closed. No fallback to `CandleStore.insert()`, PostgreSQL, another store, or an unfenced path.

### 2.4 Required G1 tests

Tests must assert persisted state and transaction outcomes, not merely method calls:

- valid current lease commits one batch;
- missing, wrong-name, wrong-owner, wrong-generation and expired leases leave DB fingerprint unchanged;
- expiry boundary is deterministic;
- lease takeover racing a writer cannot allow the stale generation to commit;
- same-payload replay is idempotent;
- conflicting replay rolls back the full batch;
- malformed row in the middle of a batch leaves no partial rows;
- injected failure after an earlier row insert rolls back the entire batch;
- empty batch creates no file, table, WAL or mutation;
- Paper Gate token is rejected as a T0 capability;
- test proves the Gateway and LeaseStore use the same transaction/database authority.

### 2.5 G1 unresolved implementation decisions

Before coding, inspect the actual T0 connection/store interfaces and decide, without adding a second writer authority:

- whether Gateway owns a connection factory or receives a transaction-scoped connection;
- how the existing `insert_fenced()` implementation is reused without exposing a bypass;
- how the lease authority shares the exact transaction connection;
- how the existing schema's candle identity and conflict behavior map to the contract;
- how the trusted clock is injected in production and deterministic tests.

These decisions must be recorded in the implementation PR before implementation begins.

## 3. P1 — Paper Writer Gate

### 3.1 Proposed public boundary

Retain the frozen operations, but make token lifecycle explicit:

```python
class PaperWriterGate:
    def admit_writer(self) -> PaperWriterToken: ...
    def release_writer(self, token: PaperWriterToken) -> None: ...
    def begin_drain(self, *, timeout_seconds: float) -> DrainResult: ...
    def reopen(self, *, expected_generation: int) -> int: ...
```

A token must be opaque, non-transferable by accidental serialization, bound to `paper_only`, gate identity and generation, and released through an explicit context-manager/finally-safe lifecycle. The exact public token fields must not permit caller-forged admission.

### 3.2 Cross-process and crash-safety requirement

An in-process mutex or process-local active-writer counter is insufficient.

The implementation design must answer:

- What durable coordination authority serializes admission, drain and reopen across processes?
- How does a writer retain its admission protection for the complete mutation lifetime?
- How does a crashed process release its admission without an unsafe timeout-based assumption?
- How is generation persisted and incremented so tokens from before restart/reopen cannot become valid again?
- How does the drain owner prevent new admissions while waiting for existing writers?
- How are process crashes during admission, release, drain and reopen recovered?

A heartbeat/TTL alone is not proof that a process has stopped writing. Do not reclaim an expired token and report DRAINED unless the design also fences the old process so it cannot continue or resume a write.

The selected coordination mechanism must be compatible with the supported runtime platforms. Since development is PC-first on Windows while Codemagic may run on Linux, platform-specific locking behavior must be explicitly tested on both supported platforms before production use.

### 3.3 State machine semantics

Freeze the exact transitions:

- `OPEN -> DRAINING`: atomically stop new admissions.
- `DRAINING -> DRAINED`: only after all admitted writer protections are released and zero active writers are proven.
- Drain timeout: return/raise an explicit timeout result; remain fail-closed in `DRAINING`; never claim `DRAINED`.
- `DRAINED -> OPEN`: only through explicit guarded reopen, with no active writers and an expected current generation; increment generation before new admission.
- Repeated release of the same token is idempotent.
- A stale token cannot release, mutate under, or reopen a newer generation.
- A process restart cannot silently reopen the Gate.
- Unknown/corrupt coordination state fails closed.

The implementation must define whether a successful `begin_drain` call returns only after DRAINED is proven, or returns a typed intermediate state. It must not overload a boolean with ambiguous meanings.

### 3.4 Storage bootstrap boundary

The Gate must be able to reject a writer before the Paper database is opened or created.

Therefore P1 must explicitly identify the Gate's own coordination storage/locking resource and its path, lifecycle, permissions and crash behavior. It must not implicitly bootstrap `PAPER_DB` merely to decide whether a writer may open `PAPER_DB`.

P1 does not yet authorize implementing the complete P2 path/symlink validation. However, its API must accept a future pre-open admission hook so P2 can enforce path identity before opening the Paper DB.

### 3.5 Required P1 tests

- admission succeeds only in OPEN;
- DRAINING rejects a new writer before Paper DB open/create;
- DRAINED is impossible while any valid writer remains active;
- drain waits for multiple writers and completes only after all release;
- timeout remains fail-closed and does not report DRAINED;
- double release is idempotent;
- stale-generation release is rejected/no-op without decrementing current writers;
- reopen requires DRAINED and the exact expected generation;
- restart invalidates old tokens and does not silently reopen;
- process killed while holding admission cannot permanently wedge the gate;
- process killed during drain/reopen recovers fail-closed;
- two independent processes racing admission and drain cannot violate the state machine;
- tests verify no Paper DB file/WAL is created by rejected admission;
- T0 lease tokens are rejected as Paper capabilities.

## 4. Shared interface and test rules

- T0 lease tokens and Paper writer tokens are distinct types and authorities.
- Capability validation occurs before mutation; no rejected path may fall back to an unguarded writer.
- Errors are typed and stable; internal SQL/OS details are not exposed as public contract.
- Tests use temporary isolated paths, synthetic data and deterministic clocks.
- Concurrency tests use real processes where cross-process behavior is claimed.
- Tests assert before/after database fingerprints and absence of files on rejected pre-open paths.
- Required tests cannot be skipped to obtain a pass.
- Codemagic evidence must identify the exact PR head SHA, workflow, status and test counts.
- Windows-specific locking tests are required for the PC-first runtime; Linux Codemagic tests alone do not prove Windows behavior.
