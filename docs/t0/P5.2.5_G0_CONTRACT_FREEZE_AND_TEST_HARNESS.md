## 2. T0 Gateway contract (frozen for G1)

Proposed public boundary:

```python
from dataclasses import dataclass
from collections.abc import Sequence
from typing import Callable

@dataclass(frozen=True)
class LeaseFence:
    lease_name: str
    owner_id: str
    generation: int

class T0WriteGateway:
    def insert_batch(
        self,
        candles: Sequence[Candle],
        *,
        lease_token: LeaseFence,
        now_ms: Callable[[], int],
    ) -> int: ...

    def read_window(self, symbol, timeframe, start, end): ...
    def close(self) -> None: ...
```

Contract:
1. The Gateway is the only authorized canonical T0 candle commit boundary.
2. `lease_token` is mandatory and must carry lease name, owner and generation.
3. Lease existence, owner, generation and expiry are validated inside the same database write transaction as the candle batch.
4. A batch is atomic: all accepted rows commit together or none do.
5. Replaying identical candle identities is idempotent; conflicting payloads fail without partial mutation.
6. Missing, expired, stale, wrong-owner or wrong-generation credentials fail closed.
7. Paper Writer Gate tokens are a different capability and must never be accepted as T0 lease credentials.
8. PostgreSQL canonical writes remain disabled until equivalent fencing is separately specified and tested.

Error contract: invalid capability, stale lease, invalid candle or conflicting identity raises a typed Gateway error; transaction failures roll back and propagate as failure. No silent fallback to an unfenced store method.

## 3. Paper Writer Gate contract (frozen for P1)

Proposed public boundary:

```python
class PaperWriterGate:
    def admit_writer(self): ...
    def begin_drain(self, *, timeout_seconds): ...
    def reopen(self, *, expected_generation): ...
```

Contract:
1. Scope is explicitly `paper_only`; tokens are not valid for T0.
2. States: `OPEN`, `DRAINING`, `DRAINED`.
3. Admission succeeds only in OPEN and returns a generation-bound token.
4. DRAINING rejects new admissions and waits for admitted writers to release.
5. DRAINED is observable only when active writer count is exactly zero.
6. Timeout never reports DRAINED and leaves the gate fail-closed.
7. Release is idempotent; stale-generation tokens cannot release a current writer.
8. Reopen requires zero active writers and an explicit expected generation.
9. Gate coordination must be safe across processes; an in-process mutex alone is insufficient.

## 4. Storage identity and lifecycle contract (frozen for P2)

- T0 canonical storage and Paper storage are distinct physical SQLite files.
- T0 path comes only from the T0 configuration; Paper path requires explicit `PAPER_DB`.
- No Paper fallback to `MARKET_DATA_DB`.
- Resolve absolute/canonical path identity and symlink aliases before opening either DB.
- Missing path, path alias, ambiguous configuration or rejected admission fails before opening or creating a file.
- Constructors and read APIs do not create directories, DB files, WAL files, tables or indexes.
- Schema initialization is explicit and admitted by the appropriate writer capability.
- Kraken Spot remains a separate isolated store and cannot become a Futures canonical writer.

## 5. Read-only contract

Read operations must not issue DDL/DML, create a file, initialize schema, repair state, or update timestamps/baselines. This applies to:
- T0 status/health/snapshot APIs.
- Paper ledger snapshot and audit reads.
- Paper equity snapshot and dashboard read endpoints.
- Pipeline readiness and health checks.

Any operation that persists equity, audit, status or control-budget data is a writer and must be named/documented and admitted through its correct gate.

## 6. Error and fail-closed semantics

- Configuration errors are explicit and stop before storage access.
- Capability errors are explicit and stop before mutation.
- Drain timeout is a failure, not a partial success.
- Transaction failure rolls back the full unit of work.
- No fallback from Gateway to direct CandleStore/Postgres insert.
- No fallback from Paper DB to T0 DB.
- No fallback from rejected writer admission to unguarded mutation.

## 7. Test harness rules

- `market_data.test_gateway_runtime`
- `paper_execution.test_writer_gate_runtime`
- `pipeline.test_paper_writer_isolation_runtime`

Every new integration test must:
1. Create its own temporary directory and DB path.
2. Use synthetic candles/state and deterministic timestamps.
3. Remove runtime/storage/exchange credentials from the process environment.
4. Assert rejected operations do not create the target DB or WAL file.
5. Never infer that a test is isolated merely because its filename starts with `test_`.
6. Never access a developer, PC, Android, canonical, shared, or exchange-backed DB.
7. Avoid real network calls and never instantiate a live exchange adapter.
