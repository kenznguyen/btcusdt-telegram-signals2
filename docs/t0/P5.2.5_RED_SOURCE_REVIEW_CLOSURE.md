## 2. Scope and evidence boundary

This report consolidates the six-part AST writer/mutator scan, the source-path findings recorded during review, and the latest user-supplied Codemagic RED results.

The scan is a candidate inventory, not proof that every candidate is a production database write. Classification distinguishes production writers, schema/state initialization, read paths, test fixtures, and isolated stores. ## 3. Confirmed architectural blockers

### 3.1 T0 canonical candle storage

1. `market_data.store.CandleStore` has constructor-time schema/WAL side effects.
2. `CandleStore.insert()` remains an unfenced write path.
3. `CandleStore.insert_fenced()` performs lease/generation checks in its write transaction, but callers are not forced through a single Gateway.
4. `market_data.sync.sync_window()` can fall back to `store.insert()` when `write_fence` is absent; the CLI path was identified as a bypass candidate.
5. `market_data.feeder_service` has a startup schema side effect through `store.insert([])`.
6. `PostgresCandleStore.insert()` is a raw PostgreSQL write path without equivalent fencing. PostgreSQL must remain disabled as canonical writer until equivalent fencing and acceptance tests exist.
7. Lease management (`LeaseStore`) and runtime status publication (`FeederRuntimeStatusStore.publish()`) are additional state writers. Their authority and transaction boundaries must be explicit; a status publish is not a candle write.

**Required GREEN contract:** all canonical candle writes go through one Gateway; lease owner, generation, expiry validation and candle commit are atomic; no direct insert, facade, CLI, startup or alternate backend bypass is possible. Schema initialization is explicit and separately authorized.

### 3.2 Paper database isolation and writer admission

1. `PaperLedger` constructor initializes schema and state, so construction can write.
2. Ledger operations write orders, books, positions/state, strategy state and audit records.
3. Equity helpers create schema/indexes and may initialize account configuration, daily baselines and equity history. A function named `snapshot()` is not guaranteed read-only when it calls `ensure()`.
4. Risk-control helpers initialize schema and mutate kill/pause state.
5. `pipeline.api.control_permit()` directly creates and mutates `paper_control_budget`; it must not use `MARKET_DATA_DB`.
6. `equity_snapshot()` was identified as persisting equity history, despite its snapshot/read-oriented endpoint name.
7. Paper mutators and schema initialization do not yet have one enforced Paper Writer Gate.

**Required GREEN contract:** Paper persistence uses an explicit `PAPER_DB`, physically separate from canonical T0 storage. All Paper schema initialization and mutations require Gate admission. DRAINING rejects new writers; DRAINED means zero active writers; timeout fails closed; tokens are bound to a generation and released idempotently. Missing Paper DB or canonical-path/symlink alias must fail closed before opening or creating a database. Read endpoints must not perform DDL/DML.

### 3.3 Other stores and migration paths

- Kraken Spot storage is an isolated Spot store, not a canonical Futures writer. It must remain physically separate and must not feed the canonical Futures strategy implicitly.
- Shadow migration and schema migrations are privileged write paths. They require explicit authorization and must refuse to proceed while a Feeder lease is active or Paper writers are not drained.
- Test modules and migration fixtures intentionally create/update/delete temporary test data. They are not production writer paths, but their fixtures must remain isolated from canonical paths.
- Read-only status, health, API and audit paths require verification that their call chains do not initialize schema or mutate state.

## 4. Consolidated required test matrix

| Area | Required acceptance evidence |
|---|---|
| Gateway lease | Valid lease succeeds; expired/wrong-generation/stale-owner rejected |
| Gateway concurrency | Takeover race cannot commit under stale generation |
| Atomic batch | All-or-nothing write and rollback on failure |
| Gateway bypass | Direct insert, facade, sync without fence, CLI and startup cannot write canonical data |
| Schema lifecycle | Constructors/read paths do not implicitly initialize canonical schema |
| Paper Gate lifecycle | OPEN, DRAINING, DRAINED, timeout fail-closed, stale token, double release and guarded reopen |
| Paper isolation | DRAINED rejects before DB open/create; missing PAPER_DB and path/symlink aliases fail closed |
| Pipeline budget | `control_permit()` writes only to PAPER_DB and only under Gate admission |
| Paper mutators | Ledger, equity, risk, audit, pause/kill and order mutation all require admission |
| Read-only guarantees | Health, status, equity snapshot and audit reads perform no DDL/DML |
| Migration | Blocked by active Feeder lease or non-drained Paper writers; rollback and integrity verified |
| Process lifecycle | Competing processes, drain waiting, restart invalidation and stale tokens tested |
| Backend policy | PostgreSQL canonical writer disabled until equivalent fencing tests pass |

Tests must assert observable storage effects and fail-closed behavior, not merely the presence of class or method names.
