# P5.2.5 Repository-wide Writer / Mutator Inventory

Audit ref: `feature/p5-2-5-green-contracts-20261102`
Audited source tree: 200 tracked files; recursive Git tree response reported `truncated=false`.
Audit scope: all tracked Python production modules, Python test modules, SQL migration, Codemagic/CI entrypoints and all discovered `MARKET_DATA_DB` references. Android/Kotlin UI and archived workflows are not T0/Paper SQLite authorities; any future Android persistence bridge must be separately inventoried.
Status: source classification only. It does not prove runtime call-graph reachability or process isolation.

## Classification legend

- **PRODUCTION WRITER** — production code directly creates/mutates persistent state.
- **INDIRECT / DELEGATED WRITER** — production code calls a store, ledger, callback or adapter that performs writes.
- **TEST FIXTURE** — test-only setup/assertion writes to disposable test databases.
- **MIGRATION / SCHEMA** — DDL, migration or initialization; still a privileged mutation and must be explicitly controlled.
- **READ-ONLY** — opens a database read-only or performs SELECT/integrity inspection only.
- **MIXED** — module contains both read-only and write paths; classify each function, not the file as a whole.

## Cross-cutting classification of AST / SQL scan results

- Production writer: direct SQL and insert methods in market_data/store.py, market_data/postgres.py, market_data/kraken_spot_store.py, paper_execution/ledger.py, paper_execution/equity.py, paper_execution/risk_control.py, pipeline/api.py.
- Indirect/delegated writer: market_data/storage.py, sync.py, feeder callbacks/service, pipeline API Ledger calls, PaperLedger helper calls, CLI.
- Migration/schema: CandleStore and PaperLedger constructors, risk_control/equity ensure functions, market_data/migrations.py + SQL, shadow migration scripts.
- Test fixture: all `test_*.py` and `paper_execution/shadow_migration_fixture.py`; classify SQL by file role rather than counting it as production bypass.
- Read-only: explicit SQLite `mode=ro` paths, `PRAGMA query_only=ON`, SELECT-only API/report functions; review `equity_history.snapshot` as exception because it invokes ensure.
- Mixed: modules containing both read and write APIs must be split at function/capability boundaries, not given one file-level label.

## Mandatory writer inventory closure checks

1. Codemagic AST scan must enumerate every tracked `.py` file, not a hard-coded subset; include root scripts, `ci/`, all package trees, and SQL/YAML/shell entrypoints.
2. Emit candidate file, line, enclosing function, SQL verb/API, path expression and classification. Unknown/dynamic path or indirect call = UNCLASSIFIED and fails inventory closure.
3. Test and fixture candidates may be excluded from production writer totals only with path-based evidence and disposable DB assertions.
4. Every production/indirect writer must map to exactly one capability: T0WriteGateway or PaperWriterGate. No dual-purpose token.
5. Every read-only path must be checked for constructor/schema side effects; read-only must not create files, tables or indexes.
6. Verify no second process can open canonical T0 SQLite read-write outside Gateway. SQLite has no per-table ACL; enforce process/filesystem boundary.
7. PostgreSQL canonical writes remain disabled until equivalent fencing adapter is reviewed. Kraken Spot remains physically separate.
8. A repository tree + static scan is not a runtime proof. Require transaction-race, crash/restart, drain and isolation tests below.

## Verdict

Two runtime contract suites have meaningful RED candidates, but source review now identifies unresolved production bypasses and a confirmed T0/Paper path collision. **G2 remains RED_CANDIDATES_REQUIRING_SOURCE_REVIEW; source review is not closed and GREEN implementation must not start until the follow-up inventory scan and tests below are accepted.**
