## Native test coverage
Added `native_sqlite_handle_lifecycle_test` as a second host CMake/CTest target, linked against the same pinned SQLite 3.54.1 amalgamation and compiling the production native translation unit.
Four scenarios:
1. Register an in-memory DB, read D5 through its opaque handle, close it, verify later read returns `D5_INVALID_HANDLE`, and verify repeated close returns `ALREADY_CLOSED`.
2. Zero and unknown handles fail closed for both read and close.
3. Two independent registered connections receive unique handles; closing one leaves the other readable.
4. Concurrent read and close are serialized: read either completes before close or observes invalid handle; after close completes the handle is invalid and no registry entry remains.
