## Source changes

- `NativeSqliteReadOnlySession.kt`
  - Typed native status mapping; unknown status codes fail closed.
  - Absolute-path validation before JNI.
  - Narrow bridge exposing only open-pinned-snapshot and close; no arbitrary SQL entry point.
  - Session handle ownership, idempotent close, and retry after a reported close failure.
  - Lazy native library loading; JVM tests use an injected fake bridge.
- `native_sqlite_readonly.cpp`
  - Opens only existing paths using `SQLITE_OPEN_READONLY | SQLITE_OPEN_FULLMUTEX`.
  - Checks DB and WAL sidecar readability before SQLite open; this increment intentionally accepts WAL-mode databases only.
  - Verifies SQLite runtime floor 3.37.0, exact `sqlite3_sourceid()`, and `sqlite3_db_readonly(main)==1`.
  - Starts `BEGIN DEFERRED`, verifies the anchor statement with `sqlite3_stmt_readonly()==1`, reads `sqlite_schema` on the same `sqlite3*`, and rolls back/closes on teardown.
  - Does not request `SQLITE_OPEN_CREATE`, `SQLITE_OPEN_READWRITE`, immutable URI mode, or expose arbitrary SQL.
- `CMakeLists.txt`
  - Requires the exact amalgamation directory, version number, source ID and SHA-256 values for both `sqlite3.c` and `sqlite3.h`.
  - Fails closed if any pin is missing or mismatched; no framework/system SQLite fallback.
- `NativeSqliteReadOnlySessionTest.kt`
  - Seven tests: absolute/invalid paths, native failure propagation, missing handle, idempotent close, retryable close failure, and unknown status rejection.
- `ci/check_android_t0_foundation.py`
  - Adds static guards for readonly flags, DEFERRED transaction, snapshot anchor, WAL preflight ordering, source-ID pinning and absence of create/write/immutable/arbitrary-SQL paths.
