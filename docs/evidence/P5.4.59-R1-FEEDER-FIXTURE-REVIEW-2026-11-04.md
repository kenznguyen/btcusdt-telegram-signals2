## Architecture review

1. GitHub-hosted Actions runners are appropriate for deterministic CI, isolated fixture tests, compile checks and evidence artifacts. They are ephemeral and must not be treated as a continuously running production Feeder host.
2. The existing T0 workflow runs isolated contracts with blank `MARKET_DATA_DB`, `T0_FEEDER_LEASE_DB`, Paper DB and exchange credential variables. The workflow records the exact checked-out source SHA and uploads logs even on failure.
3. The test suites use injected clocks/callbacks, fake exchange adapters, temporary directories and disposable SQLite fixtures. The process-level SIGKILL test creates its DB inside a temporary directory and uses a deterministic fake exchange; it is not a production recovery test.
4. Continuous production Feeder hosting remains a separate architecture decision. No host is selected or activated by this review. The user's PC pause remains in force.

## Review finding and change

`RecoveryPlanner.plan()` validated aligned coverage bounds and the reported gap list, but did not validate the `coverage.complete` flag. Therefore contradictory snapshots could be treated as a successful no-gap result or as a gap plan despite claiming complete coverage.

Added two regression fixtures in `market_data/test_feeder_recovery.py`:

- `complete=false` with an empty gap list must fail closed.
- `complete=true` with a non-empty gap list must fail closed.

Updated `RecoveryPlanner.plan()` to require a boolean completeness flag consistent with the gap list. Contradictory or malformed snapshots raise `ValueError` with `coverage completeness contradicts reported gaps`.
