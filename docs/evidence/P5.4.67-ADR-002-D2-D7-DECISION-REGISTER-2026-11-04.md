## 2. ADR-002 reconciliation

The old “Open implementation decisions” paragraph incorrectly described the host variant and IPC primitive as undecided. P5.4.41's explicit owner addendum already resolved those architecture choices.

The ADR has now been corrected to record as **OWNER-APPROVED ARCHITECTURE DIRECTION**:

1. Existing `regular` Android variant is the canonical host; `.paper` is the separately installed IPC client.
2. IPC is an explicit Android Bound Service with typed Binder/AIDL.
3. A custom signature-level bind permission is required.
4. The host verifies caller UID, package identity and installed signer/lineage on every call.
5. Host and client are intended to use the same controlled installed signing identity, while exact package allowlisting and per-operation authorization remain mandatory.
6. One host/one writer; no raw database capability, shadow database or fallback writer crosses to the client.
7. Strategy Core and independent AI retain separate provenance but share the host-side Shared Risk Engine and Kill Switch; paper-only, `AI_EXECUTION_ENABLED=false`.

The following remain **OPEN / NOT VERIFIED**: exact application IDs as security allowlist values; certificate digest and key custody/rotation; exact permission/component names and final manifest; Binder/AIDL DTO and compatibility details; canonical DB path/driver/schema/transaction details; backup/recovery operational choices; source/build/device/runtime conformance.

Historical P5.4.49 paired-build evidence at source SHA `621857b4568af67fcf571968f1b732558e16ccbc` records a successful build/verifier result for that run. It does not prove current installed signer identity or independently rehashed artifact payloads. P5.4.65 also found no implemented canonical IPC service in the reviewed Android source.

P5.4.66 lists engineering questions but does not approve them. Accordingly, every D2–D7 item below remains **PROPOSED / UNRESOLVED**, not accepted.

### D1 boundary (for clarity)

D1 is **PARTIALLY ACCEPTED** only for:
- Android is the canonical T0 host.
- SQLite on Android is the canonical T0 storage backend.
- Market Data and Paper Ledger share one physical SQLite file.
- Android is the intended sole canonical writer after separate activation; PC is not the canonical writer.

D1 still does **not** settle the exact app-private path/filename, stable store ID, table/domain ownership, transaction boundaries, lease placement/fencing, WAL/checkpoint policy, backup destination/security/retention or production activation. Those gaps must not be silently reassigned to D2–D7 or treated as approved.
