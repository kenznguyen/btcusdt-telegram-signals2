The earlier P5.4.27 conclusion “NOT INTEGRATED” is superseded. This is a source-level finding, not evidence that the runtime has been started or that production data has been written.

## Source findings

### 1. Scheduler and Recovery callback composition — PASS (source)

In `feeder_service.build_runtime()`:
- It requires a `T0WriteGateway`.
- `canonical_sync()` creates a `LeaseFence` using the current runtime lease generation and calls `sync_window()` with the same Gateway, observation clock and lease clock.
- Scheduler receives `sync_callback=canonical_sync`.
- Each RecoveryCoordinator callback calls `canonical_sync` through the configured retry policy.
- FeederRuntime receives this scheduler and recovery adapter.

This is the missing composition-root evidence from P5.4.27.

### 2. Explicit production path identity — PASS (source, limited to Feeder components)

In `build_production_runtime()`:
- `MARKET_DATA_BACKEND` must be SQLite.
- `MARKET_DATA_DB` is mandatory.
- `T0_FEEDER_LEASE_DB` defaults to `MARKET_DATA_DB`; if supplied, both paths are resolved and must be identical.
- Read facade is built by `create_store_from_env(values)`, which uses the same `MARKET_DATA_DB`.
- `T0WriteGateway`, `LeaseStore`, and `FeederRuntimeStatusStore` are constructed using the same resolved candle/lease path.
- No implicit schema initialization is called by this production factory.

This proves source-level path alignment for the Feeder's Candle read facade, Gateway, LeaseStore and status store when the production factory is used. It does not prove the real Android canonical path, physical file existence, permissions, WAL state, or actual runtime wiring on Android.

### 3. Remaining path authority limitation

The lower-level injectable `build_runtime()` accepts `gateway`, `lease_store`, and `store` independently and does not itself assert that they reference one physical DB. The production factory enforces the SQLite path relationship; fixture callers can still pass mismatched components unless tests or constructors add an invariant.

Paper Ledger remains outside this Feeder composition. Prior P5.4.23 source review found that PaperLedger accepts an independent path. The repository still does not establish one canonical Android path authority across T0 Feeder and Paper Ledger. This remains NOT VERIFIED.

### 4. Legacy direct candle writer surface

Current `CandleStore` source exposes explicit schema initialization and read functionality; it does not expose `insert()` or `insert_fenced()`. Current tests include an assertion that `CandleStore` has no `insert_fenced` attribute. G2 GREEN PR description also records removal of the direct writer surface and migration of consumer fixtures.

Source-level direct legacy writer removal: PASS for the inspected CandleStore surface. A repository-wide mutation-path audit across every package is not repeated in this task and remains a separate assurance item.

### 5. Test coverage gap

Current `test_feeder_lifecycle.py` includes:
- `test_build_runtime_composes_scheduler_and_recovery_without_starting_process`;
- `test_startup_recovery_renews_lease_before_canonical_sync_attempt`, which asserts Recovery calls sync_window with the supplied Gateway and a typed LeaseFence;
- production factory tests for rejecting PostgreSQL and a separate lease DB, plus constructing a SQLite runtime without starting it.

The inspected lifecycle tests do not directly invoke the Scheduler's composed callback and assert that it calls sync_window with the same Gateway and lease capability. The source composition is clear, but a deterministic fixture-only Scheduler callback integration assertion should be added.

The historical PR #125 G2 GREEN evidence reports the G2 and lifecycle suites passed on its exact tested SHA. This task did not rerun tests, and that historical run is not a new validation of the current branch SHA.
