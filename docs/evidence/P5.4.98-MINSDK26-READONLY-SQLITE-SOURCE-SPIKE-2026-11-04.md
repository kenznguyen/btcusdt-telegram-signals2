## 2. P5.4.98 source-level spike result

**Verdict: BLOCKED for adapter selection / NOT RUNTIME VERIFIED.**

The AndroidX `SupportSQLiteDatabase.beginTransactionReadOnly()` API contract describes a DEFERRED read-only transaction, but its interface default delegates to `beginTransaction()`. The framework implementation reviewed overrides the method and attempts a reflective call to `SQLiteSession.beginTransaction(TRANSACTION_MODE_DEFERRED, ...)`. If the reflective methods cannot be resolved, the implementation falls back to `beginTransaction()`, which is EXCLUSIVE and does not satisfy the required contract.

Reviewed source:
- AndroidX SupportSQLiteDatabase API/default behavior: https://android.googlesource.com/platform/frameworks/support/+/b415d049302bdc874f2cbc536fe1d47565c57b23/sqlite/sqlite/src/androidMain/kotlin/androidx/sqlite/db/SupportSQLiteDatabase.android.kt
- AndroidX FrameworkSQLiteDatabase override/reflection/fallback: https://android.googlesource.com/platform/frameworks/support/+/7148f22347ad3c1cd6e4672a56feb6941506cfa1/sqlite/sqlite-framework/src/androidMain/kotlin/androidx/sqlite/db/framework/FrameworkSQLiteDatabase.kt
- AndroidX SQLite release history: https://developer.android.com/jetpack/androidx/releases/sqlite
- Android framework API 35 DEFERRED read-only method: https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/database/sqlite/SQLiteDatabase.java

The reviewed implementation contains a compatibility-sensitive reflection path. Source inspection cannot establish that hidden/reflection access succeeds on API 26 with this app's target SDK 35 and actual device build. The fallback is explicitly rejected. A method call returning normally is not proof that the transaction used DEFERRED mode.

Decision:
- Do not add an AndroidX dependency merely to expose the API.
- Do not implement or select an adapter in this increment.
- Do not use EXCLUSIVE or IMMEDIATE as substitutes.
- Keep minSdk 26 read-only consistent transaction **BLOCKED / NOT RUNTIME VERIFIED**.
- Require future API 26+ device/runtime proof for the exact pinned dependency, target SDK, implementation class, actual DEFERRED path, read-only enforcement, stable snapshot, and no DB/WAL/SHM mutation. This needs separate device/instrumentation authorization.

A pure source gate was added. It accepts only adapter-supplied evidence that identifies a concrete implementation, reports DEFERRED, confirms read-only enforcement and confirms no fallback. The gate validates evidence fields only; it does not prove their runtime truth.

## 3. P5.4.96 D5 decisions implemented at source level

The following approved recommendations are represented by `CanonicalD5SchemaContract`:

1. SQLite minimum feature floor: 3.37.0; older or unparsable versions fail closed.
2. Exact, positively probed table-list result shape: `SELECT * FROM pragma_table_list` with columns `schema,name,type,ncol,wr,strict`.
3. Missing table-list result shape fails closed; additional, missing or reordered columns fail closed.
4. Reject `virtual`, `shadow` and unknown object types for this release.
5. Compare table-list table/view identities with `sqlite_schema` after only the versioned `sqlite_*` internal-object exclusion.
6. Validate exact output-column shapes for `table_xinfo`, `index_list`, `index_xinfo` and `foreign_key_list`.
7. Define D5 canonical envelope v1 field inventory for runtime identity, catalog SQL, table columns, index list, index columns and foreign keys.
8. Preserve exact catalog SQL text as UTF-8 input; do not normalize SQL.
9. Exclude `rootpage` from logical schema inventory.
10. Record exact SQLite source ID, but do not impose an owner-unapproved source-ID allowlist.

No canonical byte serializer or SHA-256 schema-digest implementation was added. This increment defines the v1 source contract and validation boundaries only.
