## Related Python persistence boundary

- `paper_execution/ledger.py` accepts its own `db_path`, creates parent directories, opens SQLite, enables WAL, and creates Paper Ledger, order, audit, strategy and equity-history tables during initialization.
- `read_snapshot(db_path)` is read-only and refuses to create a missing database.
- `market_data/feeder_service.py` composes Python T0 CandleStore, T0WriteGateway, LeaseStore and FeederRuntime from environment-provided paths; its production factory currently requires SQLite and enforces the lease DB path to resolve to the same file as `MARKET_DATA_DB`.
- These Python components do not prove that Android owns or composes them. They are not evidence of PC canonical ownership; they expose an integration/deployment gap against the confirmed Android-first target.

## Findings

### F1 — Existing Android durable state is SharedPreferences-centric
The inspected Android monitor and dashboard persist substantial operational/UI state in `strategy_state_v1`. This includes strategy cursor/state and alert/scanner/order-book snapshots. It is app-local preferences storage, not a demonstrated T0 OHLCV database.

### F2 — No Android canonical T0 SQLite composition is established
The inspected app dependency file does not declare Room/SQLite/DataStore, and the inspected Android source files do not show a canonical SQLite path provider, schema owner, CandleStore, LeaseStore, T0WriteGateway or Feeder composition root. This is a bounded finding, not proof that no such code exists anywhere in every branch/source set.

### F3 — Paper Ledger is not shown as Android-local persistence
The inspected PaperOrderHistory component renders server-provided order snapshots. The Python PaperLedger owns a separately injected SQLite path. No reviewed Android composition connects this UI to an Android-local Paper Ledger database.

### F4 — Canonical ownership must not be inferred from existing preferences
Do not promote `strategy_state_v1` to canonical T0 storage. Do not place candles, paper orders, risk state or lease fencing into ad-hoc JSON preferences. The Android-first architecture needs an explicit storage/composition design and migration/recovery contract.

## Required implementation gaps before Android canonical activation
1. Define one Android canonical path authority and its app-private durable location.
2. Define the canonical T0 schema and migrations for OHLCV, continuity/gap metadata, lease/fencing, runtime status and recovery metadata.
3. Define how the Android Feeder is composed and prove there is exactly one canonical writer.
4. Decide explicitly whether Paper Ledger shares the T0 SQLite file or uses a separate Android-owned database with a documented transaction/recovery boundary. The Android-first decision alone does not settle this.
5. Define Risk State, Paper State, equity history and audit persistence ownership and atomicity.
6. Define backup/restore and WAL-consistent snapshot/restore across the selected stores.
7. Define a controlled PC read/analysis data interface that cannot become a second canonical writer.
8. Add fixture-only contracts for path identity, fail-closed writer fencing, process restart and recovery before any device/runtime validation.
