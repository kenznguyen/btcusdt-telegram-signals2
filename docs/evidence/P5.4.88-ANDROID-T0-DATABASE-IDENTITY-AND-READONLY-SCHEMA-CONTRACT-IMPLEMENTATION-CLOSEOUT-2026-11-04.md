## 2. Implementation

### 2.1 Identity domains

CanonicalRuntime.kt now exposes CanonicalDatabaseRoleId for the stable logical T0 role. The former generic identity token is no longer represented as a physical DB identity.

CanonicalDatabaseContracts.kt adds:
- CanonicalDatabaseInstanceId: opaque persisted identity for one physical database lineage. It can only be constructed from an already persisted value; no generator, default, auto-stamping or provisioning path exists.
- CanonicalDatabaseLineage.restored(): models a verified restore preserving the same instance lineage.
- CanonicalDatabaseLineage.fork(): models an explicit clone with a different instance ID and parent lineage; reusing the parent ID is rejected.
- Distinct BackupId, RestoreEpoch and LeaseGeneration value types.
- Immutable MigrationDescriptor metadata with SHA-256 calculated from exact supplied migration bytes.
- AppliedMigration and SchemaVerificationStatus domain values.
- ReadOnlySchemaVerifier: a pure in-memory evidence verifier for role/instance matching, ordered database-wide migration catalog, unknown/duplicate/gapped migrations, checksum mismatch, incomplete chain and schema-digest mismatch.

The verifier accepts already captured evidence values. It does not open SQLite, read files, execute SQL, run migrations or perform repairs. It is not yet a SQLite read-only adapter or production database verifier.

### 2.2 Identity and migration safety

- CanonicalDatabaseRoleId is not interchangeable with CanonicalDatabaseInstanceId.
- No instance ID is generated or inferred from package, path, app version, device ID, timestamp or file hash.
- Missing instance identity remains IDENTITY_UNKNOWN; no automatic replacement is created.
- BackupId, RestoreEpoch and LeaseGeneration remain separate identity/fencing domains.
- Migration descriptor checksum and applied checksum are separate values and must match.
- Unknown migration, duplicate/gapped sequence, incomplete applied chain, role mismatch, instance mismatch and schema digest mismatch fail closed.
- The migration verifier is a pure domain contract; no SQLite registry DDL, schema introspection or database adapter was implemented.
