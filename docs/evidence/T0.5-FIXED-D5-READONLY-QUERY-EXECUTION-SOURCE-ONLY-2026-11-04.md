## 1. Scope implemented

- Added a fixed-query D5 reader entry point on the existing native snapshot handle: `NativeSqliteReadOnlySession.readD5Snapshot()`.
- JNI `nativeReadD5Snapshot(handle)` reuses the exact `sqlite3*` already registered by T0.3/T0.4. It does not open another connection, begin another transaction, or return the connection to a pool.
- Native code keeps the DEFERRED read transaction opened and anchored by `nativeOpenPinnedSnapshot`; every D5 query runs on that same handle. The caller still owns session close/ROLLBACK.
- Added no arbitrary SQL parameter or execute-SQL API. All SQL statements are literal fixed templates. Table/index names are passed through `sqlite3_bind_text` values to table-valued PRAGMA functions.
- Every statement is prepared through one guard that requires `sqlite3_stmt_readonly(stmt) == 1` and validates the exact result-column count and names before stepping.
- Query families implemented:
  1. Runtime identity: `sqlite_version()`, `sqlite_source_id()`.
  2. Main-schema table classification: `pragma_table_list`; requires exact `schema,name,type,ncol,wr,strict` shape.
  3. Catalog: `main.sqlite_schema`, exact SQL text, fixed `sqlite_*` internal-object exclusion.
  4. `pragma_table_xinfo` for every accepted table and view.
  5. `pragma_index_list` for tables, excluding SQLite-owned `sqlite_*` indexes.
  6. `pragma_index_xinfo` for every visible index, preserving key/auxiliary/expression/rowid, DESC and collation fields.
  7. `pragma_foreign_key_list` for tables.
- Scope is deliberately main-schema only. Virtual, shadow, unknown object types, missing catalog SQL, unsupported result shape, partial rows, and payload/row/string limits fail closed.
- Native transport uses private `D5WT` version 1 framing; it is not the canonical digest format. Kotlin strictly decodes bounded lengths, UTF-8, booleans, counts, status and trailing bytes, validates table-list/catalog parity, table_xinfo row counts, index-list/catalog parity and foreign-key table ownership, then calls the frozen `CanonicalD5Serializer.serialize` as a pure envelope/identity validation step.
- The resulting `D5SchemaEnvelope` can be passed to the existing canonical serializer/digest API. No digest is accepted from native code.
