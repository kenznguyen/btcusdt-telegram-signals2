## 1. Scope

Continued the approved P5.4.8 fixture-only plan. This increment binds each split-store manifest entry to the actual SQLite backup image and its read-only inspected contents.

Implemented in CI test support:
- `derive_snapshot_identity()` reads the fixture database in read-only mode and derives:
  - logical SHA-256 over canonical schema/data projection;
  - per-table row counts;
  - fixture high-water mark, defined here as the sum of table row counts;
  - SQLite `PRAGMA user_version` as the fixture schema version.
- `publish_split_store_backup_set()` compares the supplied barrier, logical snapshot ID, row-count high-water mark and schema version with the staged backup. It derives and writes the physical backup-file SHA-256, logical SHA-256 and table-count map into the manifest only after inspecting the actual staged database.
- `verify_split_store_backup_set()` validates the exact directory inventory and manifest, then independently reopens both databases read-only and compares physical SHA-256, logical SHA-256, row counts/high-water mark, schema version and table-count map.
- The verifier rejects missing or extra files and malformed manifest data. It does not initialize or repair databases.

New tests:
1. Positive binding of both store snapshots to their content and distinct schema versions.
2. Tampered manifest physical content hash rejection.
3. Swapped market-data/paper-ledger database image rejection.
4. Missing database image rejection.

The fixture uses distinct `PRAGMA user_version` values (3 and 5) to prove store-specific schema version binding.
