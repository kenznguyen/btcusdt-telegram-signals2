## Required identity evidence — all gates must pass

| Gate | Required evidence | Acceptance condition | If absent |
|---|---|---|---|
| 1. Intended origin | Exact HTTPS origin (scheme + hostname + port) supplied/confirmed by the operator, plus intended environment designation | Origin is explicitly identified as the isolated Paper backend; no URL userinfo, query or fragment | BLOCKED; do not resolve or probe an assumed host |
| 2. TLS identity | Certificate chain, validity interval, SAN hostname match, issuer and trust result obtained through an approved independent channel | Certificate is valid for the exact hostname and trusted; no disabled TLS verification | BLOCKED; no request |
| 3. Deployed build identity | Server-reported immutable build/source SHA or signed deployment manifest, obtained through trusted deployment metadata rather than unauthenticated `/health` | Exact SHA matches the reviewed/deployed commit intended for this test; provenance is independently attributable | NOT VERIFIED; do not treat service label or user-agent as proof |
| 4. Authentication separation | Configuration-owner attestation that `MARKET_DATA_TOKEN` and `CONTROL_TOKEN` are both provisioned, non-empty and distinct; validation must not reveal values | Distinct credentials; values never appear in logs, reports, screenshots or command output | BLOCKED; do not send credentials |
| 5. Storage target | Exact configured DB backend and canonical path/instance identity, with operator evidence of its role and permissions | Target is a disposable isolated Paper DB or a verified read-only replica/copy; it is not the canonical production DB | BLOCKED; no DB/API read |
| 6. Hummingbot identity | Exact Hummingbot server/origin identity and connector configuration evidence | Target is the intended isolated market-data service; no exchange trading credentials or order permissions are configured | BLOCKED; do not call routes that can fetch Hummingbot |
| 7. Execution safety | Effective runtime configuration evidence for `AI_EXECUTION_ENABLED=false`; no live exchange credentials or execution route enabled | Explicit false at the deployed runtime, not merely a repository default | BLOCKED; no runtime interaction |

Evidence must be sanitized. Record presence, distinctness and validation outcomes, never secret values, private keys, bearer tokens or full credential-bearing environment dumps.

## Endpoint selection after all gates pass

A separate explicit authorization is required even after the identity contract is complete. The first probe, if authorized, must be narrowly scoped to one selected route and one confirmed isolated target.

Provisional source-level candidates from P5.4.56:
- `GET /v1/system`
- `GET /v1/intelligence`
- `GET /v1/candles`
- `GET /v1/paper`
- `GET /v1/audit`

These candidates are not runtime-certified and are not blanket permission to call them. Select only the route needed for the test and confirm its required backing files/stores are the isolated targets.

## Explicit denylist for identity/no-write probes

- `GET /v1/equity`: excluded; P5.4.55 established that it can initialize PaperLedger and persist equity history.
- `GET /v1/order-book`: excluded; may call Hummingbot and update in-process cache.
- `GET /v1/decision`, `GET /v1/signals`, `GET /v1/quality`: excluded from offline/no-network probes; call paths may fetch/cache Hummingbot snapshots.
- All POST paper controls (`evaluate`, `pause`, `cancel`, `kill`, `reset-kill`): prohibited during identity verification.
- `GET /health`: may report process status but is not identity or provenance evidence.

HTTP method alone does not establish side-effect safety. Re-evaluate the exact route call graph and target environment before each separately authorized probe.

## Decision record

The identity contract is satisfied only when all seven gates have independently attributable evidence. A missing, ambiguous, stale or unverifiable item leaves the probe **BLOCKED**. A repository default, a successful DNS lookup, a healthy process, an unauthenticated health response, or a URL entered into the Android app is not sufficient identity evidence.
