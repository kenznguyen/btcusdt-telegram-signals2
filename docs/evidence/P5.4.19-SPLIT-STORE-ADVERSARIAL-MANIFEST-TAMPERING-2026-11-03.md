## 1. Scope

Added four adversarial fixture tests to the existing split-store backup verifier suite:

1. **Re-hashed semantic mutation:** modifies a candle's `close` value in the market-data backup and updates the manifest's physical `content_sha256` to the new, valid SHA-256. The verifier must still reject the image because its logical snapshot identity no longer matches.
2. **Table-count tampering:** increments one manifest table count and also increments the declared high-water mark, preserving the manifest's internal sum. The verifier must reject it against actual read-only database counts.
3. **High-water tampering:** changes a store's high-water mark without changing its table counts. The verifier must reject the inconsistent manifest.
4. **Schema-version tampering:** changes the paper-ledger manifest schema version while leaving the database's `PRAGMA user_version` unchanged. The verifier must reject it.

These tests are deliberately adversarial: case 1 proves a matching physical file hash alone cannot authorize semantically different data; case 2 avoids relying only on the manifest's internal arithmetic check.

No production/runtime implementation was changed in this increment. Only `ci/test_backup_restore.py` was extended, including the required `hashlib` import.
