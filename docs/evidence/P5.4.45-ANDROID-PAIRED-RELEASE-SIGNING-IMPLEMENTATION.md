### 2.2 Manual-only GitHub Actions workflow

Added `.github/workflows/android-release-pair.yml`:
- Only trigger: `workflow_dispatch`; no push, pull_request or schedule trigger.
- Restricted to the existing approved branch `feature/p5-4-1-post-merge-validation-20261103`.
- Requires a full source SHA and enforces equality with `GITHUB_SHA` and checked-out HEAD.
- Uses only `contents: read`.
- Checks presence of `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`; requires alias `btc-chart-release`. It does not print secret values.
- Restores the keystore to runner-temporary storage with restrictive file permissions and removes it in an `always()` cleanup step.
- Runs Android unit tests, builds `assembleRelease` and `assembleParallel`, then verifies both outputs before upload.
- Uploads the paired APKs, source SHA, test reports and verification JSON only after successful verification; artifact retention is 14 days.
- Explicitly keeps `AI_EXECUTION_ENABLED=false` and exchange/DB environment variables empty.

### 2.3 Real APK verification gate

Added `ci/verify-android-release-pair.py`. For both actual APK files it:
- verifies the exact checkout SHA;
- checks package ID, app label, launcher activity and version metadata with Android SDK `aapt`;
- verifies APK signatures with `apksigner`;
- extracts each signer certificate SHA-256 fingerprint;
- rejects signer mismatch;
- checks regular/.paper versionCode and versionName relationship;
- computes each APK's SHA-256 and byte size;
- emits machine-readable evidence only after all checks pass.

Added `ci/test_android_release_pair.py` with synthetic fixtures for matching signer success, signer mismatch, invalid package/version, missing signer, ambiguous metadata and stale/malformed source SHA.

Updated `ci/test_ci_policy.py` to allow exactly this manual Android release workflow and enforce its manual-only, exact-SHA and shared-release-signing policy. The existing P5.4.1 preflight now executes the verifier fixture suite.
