## C. Architecture and security findings

1. ADR-002 requires the regular Android package to be the sole canonical SQLite owner; `.paper` must be an authenticated IPC client; PC must remain read-only.
2. Current Android source has only a metadata/path candidate and pure contracts. It does not open or own canonical SQLite.
3. Current Python production composition is capable of constructing a Python-side SQLite writer and lease store. It is not connected to Android through ADR-002 IPC. Starting that composition on PC would violate the selected canonical-writer ownership boundary.
4. The existing Android `StrategyMonitorService` is not the canonical IPC host; the source review recorded its `onBind()` as null. The main manifest declares no canonical exported service/AIDL/signature permission.
5. The release signing configuration reads environment-backed keystore values. Build declarations do not prove installed host/client signer equality or signer lineage.
6. D5 golden-vector success proves deterministic encoding of supplied in-memory fixtures; it does not prove schema extraction from a real SQLite database or consistent-snapshot behavior.

## F. Required conditions before any next implementation/runtime gate

1. Keep Android regular as sole canonical host, `.paper` as IPC-only client, and PC as read-only compute. Do not start the Python production Feeder as a PC writer.
2. Resolve the minSdk 26 read-only consistent-snapshot primitive without accepting an unproven reflection fallback; obtain a precise implementation/runtime compatibility decision before adapter selection.
3. Complete the approved Android SQLite adapter boundary: no-create read-only open, one consistent read transaction, runtime capability probes, schema introspection, identity persistence and migration authority.
4. Implement and test the regular-host Feeder/Gateway/lease composition against the same Android SQLite file; do not create a second writer or second database.
5. Implement ADR-002 authenticated typed IPC and prove `.paper` cannot open/create a local canonical DB or bypass host authorization.
6. Integrate Core and independent AI paper intents through one Shared Risk Engine/Kill Switch and one Paper Ledger boundary; preserve separate signal provenance.
7. Define and verify WAL-consistent backup/restore across all canonical state domains before T0-D.
8. Obtain separate authorization for Android device/path preflight, SQLite access, Feeder runtime, backup/restore, exchange connectivity or any writer activation. These are not authorized by this audit.
