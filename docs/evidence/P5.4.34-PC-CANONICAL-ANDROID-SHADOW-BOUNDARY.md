## Authoritative owner decision

The prior P5.4.34 report incorrectly stated PC-canonical / Android-shadow. That conclusion conflicts with the user's confirmed Android-first architecture and is withdrawn.

The confirmed deployment direction is:
- **Android is the primary application, data and monitoring environment.**
- **T0 canonical SQLite is intended to reside on Android**, subject to completion of validation and explicit production activation approval.
- **Android is the initial and sole T0 canonical writer** once that approved runtime is activated. Do not enable a second writer.
- **Windows PC** is the development/analysis environment for AI training, FreqAI, backtesting and research; it is not the current canonical T0 owner.
- **GitHub** stores source, plans, evidence and artifacts; GitHub Actions runs CI against isolated fixtures.
- Any future transfer of canonical write ownership from Android to PC requires an explicit architecture decision and a controlled handover with fencing, identity verification and rollback.

This records the user's architecture decision; it does not certify that Android canonical storage or the Feeder is currently activated.

## Source observations retained from the original review

The original bounded source inspection recorded:
- Android `MainActivity` starts `StrategyMonitorService` for the inspected build.
- `StrategyMonitorService` persists monitor, strategy, scanner, alert and order-book state through `SharedPreferences("strategy_state_v1")`.
- The inspected Android Gradle dependency list did not declare Room or a SQLite wrapper.
- `market_data/feeder_service.py` is a Python T0 Feeder composition/entrypoint.
- `paper_execution/ledger.py` is a Python Paper Ledger module accepting its own `db_path`.
- The inspected Android files did not demonstrate composition of those Python modules.

These are source observations, not grounds to override the owner decision. They indicate implementation gaps between the intended Android-first architecture and the inspected source snapshot.

## Corrected findings

### F1 — Intended ownership
Android is the intended canonical T0 host and initial sole writer. The previous report's statement that Windows PC owns canonical SQLite and Android is merely `android_shadow` is **incorrect and withdrawn**.

### F2 — Implementation gap
The inspected Android service's `SharedPreferences` persistence does not itself prove that a canonical T0 SQLite store, Feeder composition, or Paper Ledger persistence has been implemented on Android. The Android canonical DB path, schema ownership, Feeder runtime composition and Paper Ledger persistence integration remain **NOT VERIFIED**.

### F3 — Python components
The current Python Feeder and Paper Ledger source components are not evidence that PC owns canonical data. Their deployment/consumption role must be aligned with Android-first: PC-side AI/backtest workflows may consume controlled data inputs, but must not independently become a competing canonical writer.

### F4 — Paper Ledger boundary
The user's Android-first decision establishes the platform direction. It does not, by itself, prove that the T0 candles and Paper Ledger must share one physical SQLite file. That cross-component database identity/schema decision remains **NOT VERIFIED** until explicitly specified and validated. Do not infer a shared file from the platform decision alone.
