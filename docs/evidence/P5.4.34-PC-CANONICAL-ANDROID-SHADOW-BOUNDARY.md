## Findings

### F1 — Android app persistence observed in inspected runtime files
- `MainActivity` starts the Android `StrategyMonitorService` for the non-parallel build and renders the dashboard.
- `StrategyMonitorService` persists monitor state, strategy state, scanner state, alert queues and order-book metrics through Android `SharedPreferences` named `strategy_state_v1`.
- The inspected Android Gradle dependency list does not declare Room or a SQLite wrapper.
- Repository code search for `SQLiteOpenHelper` and `RoomDatabase` returned no matches in the indexed default-branch corpus. This search is corroborative only; it is not a complete proof that no SQLite usage exists elsewhere or on the reviewed branch.

### F2 — Python T0 and Paper Ledger are separate SQLite components
- `market_data/feeder_service.py` is the Python production T0 Feeder composition/entrypoint and constructs the T0 SQLite storage/gateway/lease/status components.
- `paper_execution/ledger.py` is a Python Paper Ledger module that accepts its own `db_path` and initializes/uses SQLite.
- The inspected Android application files do not compose these Python modules. No Android-to-Python shared SQLite file or shared Android canonical-path provider is established by this source set.

### F3 — Architecture consequence
- The proposed requirement that Android T0 Feeder and Paper Ledger share one canonical Android SQLite file is incompatible with the confirmed PC-canonical / Android-shadow deployment boundary and is not a valid next implementation target.
- Android local `SharedPreferences` are app-local shadow/runtime state; they must not be treated as the canonical T0 market-data or Paper Ledger database.
- A separate Android SQLite shadow store, if later required, must remain explicitly non-canonical and must not be wired as a canonical Feeder writer without a new architecture decision.

## Correction to P5.4.33
P5.4.33 correctly identified independent Python PaperLedger path configuration, but its title and “shared Android SQLite identity” target implied Android was the canonical host. That implication is incorrect under the previously confirmed architecture. P5.4.33's cross-component identity conclusion is superseded by this ownership clarification; its low-level observation about independent `PaperLedger(db_path)` remains valid.
