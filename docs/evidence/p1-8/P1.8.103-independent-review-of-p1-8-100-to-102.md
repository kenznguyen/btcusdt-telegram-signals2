## 4. Findings and closure assessment

### IR2-01 — BLOCKED bypasses mandatory reconciliation

**Prior risk:** P1.8.97 allowed a generic transition from any non-terminal state to BLOCKED, which could conceal uncertainty after execution began.

**Review result: RESOLVED — DOCUMENTARY SPECIFICATION.**

P1.8.100 restricts BLOCKED to positively established pre-mutation conditions. EXECUTING, VERIFICATION_PENDING, accepted intent, possible side effect, lost response or unknown ordering route to RECONCILIATION_REQUIRED. It distinguishes canonical request state from protective quarantine and makes observer reports report-only. Quarantine cannot replace reconciliation, reverse a mutation or clear itself.

The rule is consistent with the P1.8.92 canonical distinction between in-flight ambiguity and pre-mutation eligibility blocking. The unresolved implementation of a serialized event/mutation boundary remains an implementation gate, not a contradiction in this documentary rule.

### IR2-02 — Partial cancellation could terminalize ambiguous objects

**Prior risk:** P1.8.97 permitted CANCELLED_WITH_PARTIAL_OUTCOME while ambiguous objects remained NOT_VERIFIED.

**Review result: RESOLVED — DOCUMENTARY SPECIFICATION.**

P1.8.101 requires every object in the immutable manifest to have exactly one determinate disposition. OUTCOME_AMBIGUOUS, OUTCOME_UNKNOWN, NOT_VERIFIED and IN_FLIGHT prohibit request terminality. COMMITTED requires independent verification; NOT_COMMITTED requires positive no-effect evidence. Cancellation ordering, stop-future-work, residual boundary and audit continuity are conjunctive gates.

The request terminal state therefore cannot conceal an unresolved object. Irrecoverable uncertainty remains NOT_VERIFIED/non-terminal rather than being relabelled as a completed partial cancellation.

### IR2-03 — BLOCKED to FINAL_RECHECK lacked positive no-mutation proof

**Prior risk:** the phrase “no mutation has begun under an ambiguous outcome” did not establish a complete proof.

**Review result: RESOLVED — DOCUMENTARY SPECIFICATION.**

P1.8.102 replaces the ambiguous phrase with a positive proof over the exact immutable manifest and every object generation. It reconciles intent authority, backend submission history, independent object-state oracle, all workers/queues/retries/delegates, authorization consumption and audit continuity. A serialized mutation-boundary fence is required. Missing, stale, contradictory or unavailable evidence fails closed to RECONCILIATION_REQUIRED/NOT_VERIFIED.

The rule correctly distinguishes “no intent was ever accepted” from “an intent was accepted but no effect was later observed”; the latter must be reconciled and cannot be used to claim the request never started. A fresh execution authorization is required; old authorization is not revived.
