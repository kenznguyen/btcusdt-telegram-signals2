## 3. Findings requiring clarification

### IR130-01 — MAJOR: Endpoint-level permission matrix is not yet specified

P1.8.129 correctly states that permission labels must be validated against exact API endpoints, but it provides only data families and permission classes. It does not enumerate the exact HTTP method/path, documented fine-grained token or GitHub App permission, response sensitivity, pagination and revision behavior for each proposed collection item.

Consequently, the proposal cannot yet be used to authorize collection with a least-privilege credential. A collector could otherwise request a permission broader than the owner intended or assume a permission supports an endpoint when it does not.

**Required clarification:** produce a versioned endpoint matrix using current official GitHub documentation. Include endpoint path/method, exact required permission and access level, returned fields/sensitivity, pagination, source revision/ETag availability, and necessity. Mark unsupported or uncertain endpoints excluded/UNKNOWN. Do not call the endpoints as part of this clarification.

### IR130-02 — MODERATE: Owner namespace and inherited-scope assumptions are unresolved

The repository locator uses the `owner/repository` form, but P1.8.129 refers to a parent organization and organization-level inherited access without establishing whether the owner namespace is an organization or personal account.

**Required clarification:** describe the owner as a GitHub owner namespace until its type is proven through separately approved metadata. If it is a personal account, organization-only collection paths are not applicable. If it is an organization, include only the minimum organization metadata directly affecting this repository. No org-wide enumeration is implied.

### IR130-03 — MODERATE: Secret metadata endpoint isolation needs an explicit safety gate

The proposal permits secret metadata as a possible data family but does not yet identify endpoint response schemas and prove that the chosen endpoint returns metadata only. A mistaken endpoint or response handling could expose secret material.

**Required clarification:** secret metadata collection is opt-in and excluded by default. It may be proposed only after official endpoint documentation confirms the response schema contains metadata and no secret value. The endpoint matrix must identify the exact fields allowed for retention and implement response allowlisting before persistence. If the response contract or filtering cannot be proven safe, do not call the endpoint; mark the credential binding UNKNOWN/NOT VERIFIED.
