## 1. Purpose and strict boundary

This document converts P1.8.84 and P1.8.85–P1.8.89 into deterministic future test specifications. “Executable” describes the precision required of a test case; no test code is created or run here.

All future tests must use isolated synthetic fixtures, synthetic object identities and disposable test-only storage. They must not connect to canonical T0, T1, T2, T3, T4, VPS, production credentials, real exchanges, real ledgers, real backups or external recipients. Test execution requires separate explicit scope and approval.

## 2. Required test-case schema

Every case must declare immutable test ID/spec version, linked control IDs, severity, fixture and storage namespace, non-production isolation proof, initial state for each domain, exact event sequence, deterministic concurrency barrier/fault point, expected transition, exact object scope, expected adapter call count, idempotency identity, independent oracle, audit evidence, residual classification, synthetic-only cleanup/containment, reproducibility seed, runner version and artifact provenance.

A case without an independent observable oracle is NOT_TESTABLE. A test cannot pass solely by inspecting the return value or logs of the code under test.

## 4. Concurrency and determinism

Concurrency cases must use explicit barriers/latches or deterministic event scheduling, not sleep-based timing assumptions. Each race defines one expected ordering or asserts blocking when ordering is indeterminate.

Tests distinguish event commit from client wall-clock time; registry receipt from authoritative commit; authorization from mutation; backend response from independent postcondition; source from each copy; and per-object completion from batch completion.

Fault injection is confined to synthetic components. Tests must not alter real clocks, credentials, provider settings or production-like services.

## 5. Independent oracle

The oracle must be independent of the code path under test. Depending on the future adapter, it may combine a separately controlled registry snapshot, immutable event log, direct read-only storage observation, object generation/version inspection and independent verifier record.

It must prove safety (forbidden mutation did not occur) and expected positive outcomes where applicable. Absence of an executor log is not proof of no mutation. A backend response is not independent verification.

If the oracle is unavailable, compromised, stale or shares the executor trust boundary, result is NOT_VERIFIED, not PASS.

## 6. Result vocabulary

- PASS — deterministic fixture, required safety property and independent oracle agree.
- FAIL — forbidden transition/mutation or required behavior violation observed.
- BLOCKED — required precondition/dependency unavailable.
- NOT_TESTABLE — no independent oracle or deterministic fixture.
- NOT_VERIFIED — evidence insufficient or conflicting.
- NOT_RUN — no execution occurred.

A suite is not PASS if any required vector is BLOCKED, NOT_TESTABLE or NOT_VERIFIED. Skipped cases must be reported explicitly.

## 7. Evidence package

Each future separately authorized run must preserve source SHA, test-spec SHA, workflow file SHA/run ID/artifact digest if GitHub Actions is separately authorized, runner/toolchain identity, synthetic fixture manifest and isolation proof, event schedule/fault configuration, raw observations, oracle outputs, per-object transitions, redacted logs, artifact digest and reviewer disposition.
