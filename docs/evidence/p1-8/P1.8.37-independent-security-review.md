## 3. Finding F-11 — Positive fixture wording can be read as pre-approval

**Severity:** MEDIUM — acceptance-oracle ambiguity  
**Status:** OPEN; narrow documentation clarification recommended.

P1.8.36 TB-P01 and TB-P02 say that after a valid bound timestamp and signature, the “historical policy decision proceeds.” This is directionally compatible with §2.4, but the phrase can be misread as an expected historical acceptance. That would overstate the current state because P1.8.34 leaves the authoritative revocation source, effective-time precision, timestamp uncertainty limits and equality semantics OPEN; P1.8.36 §5 also leaves the TSA profile and trust lifecycle OPEN.

**Required clarification:**
1. Fixture PASS must mean only that cryptographic binding and token/signature validation pass.
2. The historical eligibility evaluator may run only under a separately frozen V07 policy profile.
3. Until that profile and boundary parameters are frozen, the fixture's final historical disposition must remain BLOCKED/NOT DETERMINED, not ACCEPT.
4. TB-P02's late receipt must not independently change trusted-time evaluation, but it also must not bypass freshness, revocation-state or quarantine controls.

This is a wording/acceptance-oracle clarification; it does not invalidate the exact-signature binding design.

## 4. F-01 disposition

P1.8.36 resolves the central ambiguity identified in P1.8.35 at the **design-requirement level**: the timestamp imprint must cryptographically bind the exact signature bytes and immutable verification context.
