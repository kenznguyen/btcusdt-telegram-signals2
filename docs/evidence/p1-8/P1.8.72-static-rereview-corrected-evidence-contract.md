## 2. Finding F-18 — Attempt state labels are not mutually exclusive

**Severity:** LOW  
**Location:** Section 4.1, Attempt/reconciliation state.

The current attempt/reconciliation labels can overlap:
- OPEN and RETRYABLE can both describe an intent with no active request and a future retry permitted;
- EXHAUSTED and SETTLED can both appear true when every observed attempt has a definitive outcome but automated retries have stopped.

Because the section describes these as a single derived state, different implementations could choose different labels for the same history.

**Required clarification:** separate:
1. **Attempt resolution:** NO_ATTEMPTS, IN_PROGRESS, UNKNOWN_OUTCOME, ALL_RESOLVED.
2. **Retry disposition:** NOT_ELIGIBLE, ELIGIBLE, SCHEDULED, EXHAUSTED.

If a combined UI label is ever used, it must be a deterministic projection of these two fields plus proof availability. No retry number, delay or exhaustion threshold is required to define the dimensions.
