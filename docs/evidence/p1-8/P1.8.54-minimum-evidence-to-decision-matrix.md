**Date:** 2026-11-09  
**Scope:** Documentation-only planning; evidence classes E0–E4  
**Status:** MATRIX COMPLETE; NO E2/E3/E4 EVIDENCE ACQUIRED  
**Authorization:** This matrix does not authorize provider access, production probes, key operations, VPS changes, staging, restore, fault injection, or workflow dispatch.

## 1. Purpose and governing rules

Translate the OPEN parameter families in P1.8.40/P1.8.47/P1.8.49 into the smallest evidence packages capable of supporting a later owner decision. “Minimum” means the minimum distinct proof categories, not an invented sample count or duration.

Rules:
- E0 public/documentary sources establish standards semantics and candidate capability statements, not runtime behavior.
- E1 deterministic synthetic fixtures establish oracle behavior under controlled inputs, not provider or production behavior.
- E2 authorized non-production evidence validates candidate service and integration behavior in an isolated environment.
- E3 operational evidence is read-only and scoped to the real operational environment; it requires separate explicit approval.
- E4 staging evidence validates failure/recovery behavior in a controlled environment-equivalent staging domain; it requires separate explicit approval.
- Evidence from one class cannot silently substitute for a higher class.
- Every evidence item must record source SHA/version, exact configuration/profile, timestamps, identity, raw response/log/artifact digest, verifier version, result, limitations and custody/provenance.
- No numeric parameter is selected by this matrix.

## 5. Cross-cutting evidence manifest

Every evidence item should include:
1. Evidence ID, class (E0–E4), objective and linked decision IDs.
2. Source commit SHA and document/code blob SHA where applicable.
3. Environment identity and equivalence claims; exact versions/configuration.
4. Principal/operator identity and authorization record.
5. UTC timestamps, clock source and stated uncertainty.
6. Raw request/response/log/manifest and cryptographic digest.
7. Tool/verifier version and reproducible validation command.
8. Expected oracle, observed result, deviations and limitations.
9. Retention location, access controls, expiry and custody history.
10. Stop/rollback/cleanup result and explicit NOT VERIFIED items.

Do not place secrets, private keys, API credentials or raw sensitive customer data in GitHub artifacts. Store only approved redacted evidence and cryptographic references according to the evidence-retention policy.
