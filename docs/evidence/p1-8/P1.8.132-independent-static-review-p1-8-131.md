## 2. Finding dispositions

### IR130-01 — Endpoint-level permission matrix
**Disposition: SUBSTANTIALLY CLOSED — DOCUMENTARY DESIGN**

P1.8.131 provides exact candidate methods/paths and separates fine-grained permission labels from actor-role prerequisites. It correctly identifies important limitations:
- repository runner listing requires the authenticated user to have repository admin access despite the documented Administration read permission;
- collaborator listing requires write, maintain or admin privileges despite Metadata read;
- ruleset `bypass_actors` may be withheld from a caller without write access to the ruleset;
- branch-rule results include active rules only and do not replace complete ruleset inventory.

The endpoint list is a candidate allowlist, not an execution authorization. Current documentation must be rechecked immediately before any separately approved collection.

### IR130-02 — Owner namespace
**Disposition: CLOSED — DOCUMENTARY DESIGN**

P1.8.131 no longer assumes the owner is an organization. It requires an approved repository metadata response and uses owner `type` to determine whether any conditional organization scope is applicable. It correctly prohibits an organization-wide sweep.

### IR130-03 — Secret metadata safety
**Disposition: CLOSED — DOCUMENTARY DESIGN**

P1.8.131 excludes all secret metadata endpoints from the first phase. It requires a separate opt-in proposal and owner approval for any later secret metadata collection. This is safer than relying solely on an endpoint's documented omission of encrypted values.

## 3. New finding

### IR132-01 — MODERATE: Classic branch-protection endpoint omitted

P1.8.131 covers repository rulesets and effective active branch rules, but the candidate matrix does not explicitly include the classic branch-protection read endpoint:
- `GET /repos/{owner}/{repo}/branches/{branch}/protection`.

The official GitHub REST documentation identifies repository `Administration: read` as the fine-grained permission for reading branch protection. Classic branch-protection settings and rulesets are distinct configuration surfaces; omission of the former could leave required status checks, reviews, restrictions or bypass-related settings unexamined.

**Required clarification:** either add this exact GET endpoint to the candidate matrix with its documented permission, response-field allowlist, actor-role prerequisites and visibility limits, or explicitly exclude it and mark classic branch-protection coverage UNKNOWN. No endpoint call or mutation is authorized.
