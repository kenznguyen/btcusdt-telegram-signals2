## 2. Finding F-15 — OCSP nonce reference is not current

**Severity:** MEDIUM  
**Affected section:** P1.8.51 §2.2 and §2.3

P1.8.51 cites RFC 6960 for OCSP semantics and says RFC 6960 defines nonce/replay semantics. RFC 6960's nonce extension was subsequently updated by RFC 8954, which was itself obsoleted by RFC 9654. RFC 9654 updates RFC 6960 and changes the maximum nonce length to 128 octets, recommending that OCSP requesters use a minimum 32-octet nonce. Implementations conforming only to RFC 8954 may not process values above 32 octets.

This matters because P1.8.51's V07 candidate matrix includes nonce/replay as a capability, and a stale normative reference could lead to an incompatible fixture or an incorrect claim about current nonce constraints.

**Required correction:**
1. Cite RFC 9654 as the current nonce update to RFC 6960; note RFC 8954 is obsolete.
2. Distinguish protocol conformance from a project-selected nonce policy. Do not hardcode a length or claim provider compatibility before the selected profile is known.
3. Add interoperability cases for requester/responder behavior and nonce echo/omission, replay, malformed lengths, and mixed RFC 8954/RFC 9654 support.
4. Keep nonce generation policy, compatibility matrix and acceptance behavior OPEN pending profile selection and evidence.

Primary sources:
- RFC 9654: https://www.rfc-editor.org/rfc/rfc9654.html
- RFC 8954 (obsoleted): https://www.rfc-editor.org/rfc/rfc8954.html
