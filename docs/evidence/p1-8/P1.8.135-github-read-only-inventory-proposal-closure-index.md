## 4. Candidate inventory scope and explicit blind spots

P1.8.129–P1.8.133 define a candidate repository-level GET-only metadata inventory. Candidate surfaces include repository metadata, repository Actions policy/default workflow permissions, workflow metadata, environments, repository rulesets, active branch rules, classic branch protection and conditional parent-organization Actions policy.

The candidate inventory deliberately excludes or cannot fully resolve:
- collaborator roster and effective role paths because the documented endpoint requires a write/maintain/admin actor;
- repository self-hosted runner listing because the documented endpoint requires an admin actor;
- ruleset bypass actors where GitHub withholds the field from a caller without write access;
- secret metadata, secret values and secret-derived credential provenance;
- deploy keys and SSH public-key material;
- workflow source contents, action pinning, scripts, artifacts and caches;
- OIDC trust, organization identity graphs beyond the bounded conditional policy endpoint, external providers and storage permissions;
- runner host identity, filesystem, network and execution state.

All such areas remain UNKNOWN/NOT VERIFIED. A bounded metadata result cannot establish complete Option C technical enforcement.
