# P1.8.101 — Partial-Cancellation Terminality and Per-Object Outcome Closure

Date: 2026-11-09
Remediates: P1.8.99 IR2-02 (MAJOR)
Status: DOCUMENTARY DESIGN ONLY — NOT IMPLEMENTED / NOT ACTIVE / NOT AUTHORIZED

## 1. Purpose and boundary

This record defines when a request may enter CANCELLED_WITH_PARTIAL_OUTCOME after mutation has begun. It prevents a request-level terminal label from concealing any object whose outcome remains ambiguous, unverified, or in flight.

This is subordinate to the Data Deletion Safety Contract, P1.8.82, P1.8.84, P1.8.86, P1.8.92, P1.8.93, P1.8.97 and P1.8.100. It does not authorize cancellation, mutation, retry, archive or deletion. It is a documentary contract only.

## 2. Core invariant

A request may be terminalized as CANCELLED_WITH_PARTIAL_OUTCOME only when every object in the immutable request manifest has a determinate, independently supported disposition and no mutation remains in flight.

A terminal request status must never collapse or overwrite per-object status. Request-level terminality is a summary over the complete manifest, not a replacement for object-level evidence.

If even one object is OUTCOME_AMBIGUOUS, OUTCOME_UNKNOWN, NOT_VERIFIED, or may still be in flight, the request remains RECONCILIATION_REQUIRED (or the applicable non-terminal protective state). If uncertainty cannot be resolved, preserve NOT_VERIFIED; do not convert it to a successful or fully reconciled terminal result.

## 3. Object disposition vocabulary

Every manifest object must be assigned exactly one current disposition, with immutable history of prior states:

| Disposition | Meaning | Terminal eligibility |
|---|---|---|
| COMMITTED | Exact authorized object generation was mutated and independently verified | Eligible as a known partial result |
| NOT_COMMITTED | Authoritative evidence proves no mutation committed and no operation remains in flight | Eligible as a known non-mutated result |
| CANCELLED_BEFORE_INTENT | Cancellation linearized before any intent was accepted; no side effect possible | Eligible as a known non-mutated result |
| OUTCOME_AMBIGUOUS | Intent/submission may have occurred but exact result is not established | Prohibits request terminality |
| OUTCOME_UNKNOWN | Evidence/order unavailable or contradictory | Prohibits request terminality |
| IN_FLIGHT | Operation may still be executing or may commit | Prohibits request terminality |
| OUT_OF_SCOPE_RESIDUAL | Related residual/collateral object discovered outside manifest | Does not silently enter the manifest; blocks completion claim pending separate classification and governance |

COMMITTED requires independent verification of the exact object identity/generation and result. Executor response alone is not sufficient. NOT_COMMITTED requires positive proof, not absence of a success record. An object with missing evidence cannot be classified as NOT_COMMITTED.

## 4. Preconditions for CANCELLED_WITH_PARTIAL_OUTCOME

All conditions below are conjunctive and must be proven against one immutable manifest digest:

1. **Complete denominator:** every object ID and generation in the authorized manifest is accounted for exactly once in the final disposition set.
2. **No ambiguity:** zero objects are OUTCOME_AMBIGUOUS, OUTCOME_UNKNOWN, NOT_VERIFIED or IN_FLIGHT.
3. **Known committed subset:** every COMMITTED object has independent verifier evidence, durable mutation identity and exact result.
4. **Known untouched subset:** every NOT_COMMITTED or CANCELLED_BEFORE_INTENT object has positive authoritative evidence that no side effect committed and no operation remains pending.
5. **Stopped future work:** executor is durably prevented from starting any further object mutation under the cancelled request; cancellation/revocation ordering is established.
6. **Residual boundary:** all discovered residual, index, replica, sidecar, reference and collateral observations are classified. Unknown residuals prevent a completion claim.
7. **Audit continuity:** intent, mutation, cancellation, verification and final disposition events are durable, revision-linked and complete.
8. **Independent review:** lifecycle reviewer accepts the reconciliation package; the reviewer does not substitute for independent object verification.
9. **Exact scope:** no manifest expansion, object-generation replacement or authorization reuse occurred. Material scope changes require a new request and approval path.
10. **No authorization revival:** all old execution authorizations are consumed, invalidated or revoked; terminalization does not re-enable execution.

If any precondition is missing, stale, conflicting or unprovable, terminalization is rejected.

## 5. Canonical transition rule

| Current canonical state | Object-level condition | Required action | Permitted result |
|---|---|---|---|
| RECONCILIATION_REQUIRED | At least one ambiguous/unknown/unverified/in-flight object | Continue reconciliation; stop future mutations | Remain RECONCILIATION_REQUIRED |
| RECONCILIATION_REQUIRED | All objects determinate; every committed object independently verified; remaining objects positively not committed; all work stopped | Lifecycle reviewer accepts complete package; orchestrator validates exact manifest and durable events | CANCELLED_WITH_PARTIAL_OUTCOME |
| RECONCILIATION_REQUIRED | All objects determinate and all authorized operations completed rather than cancelled | Independent verification and normal completion review | VERIFICATION_PENDING, then only the appropriate verified terminal state |
| Any state | Any unresolved residual or collateral object can affect the claim | Preserve protective state and classify residual | RECONCILIATION_REQUIRED / NOT_VERIFIED |
| CANCELLED_WITH_PARTIAL_OUTCOME | Late or contradictory evidence changes an object's result | Do not rewrite history; append correction and reopen a governed reconciliation record | Prior terminal claim marked disputed/NOT_VERIFIED pending review; no automatic mutation |

The transition to CANCELLED_WITH_PARTIAL_OUTCOME is not allowed merely because the executor stopped, a cancellation request was accepted, a timeout elapsed, or a subset of objects committed.

## 6. Final disposition package

The package must include:
- immutable request ID, manifest digest and object generation list;
- per-object final disposition and evidence reference;
- independent verifier identity, authority and evidence digest for every COMMITTED object;
- positive no-effect evidence for every NOT_COMMITTED/CANCELLED_BEFORE_INTENT object;
- cancellation/revocation event and its ordering relative to each mutation intent;
- proof that no operation remains in flight and no further operation can start;
- residual/collateral inventory boundary and unresolved items (must be zero for terminality);
- audit-chain continuity and source revisions;
- lifecycle-review decision and orchestrator transition event;
- explicit statement of what was not performed and what is outside the manifest.

The package must not include secrets, credentials, payloads unnecessary to the decision, or unbounded copies of sensitive evidence.

## 7. Required negative cases

Specification additions to P1.8.94:
- NEG-AMB-03: one manifest object remains OUTCOME_AMBIGUOUS while other objects are COMMITTED/NOT_COMMITTED. Expected: request remains RECONCILIATION_REQUIRED; terminalization rejected.
- NEG-STATE-07: cancellation requested but an operation remains IN_FLIGHT or cancellation order is unknown. Expected: no terminal transition.
- NEG-VER-02: executor reports success for a COMMITTED object but independent verifier evidence is absent/conflicting. Expected: object NOT_VERIFIED; request non-terminal.
- NEG-ADP-11: unexplained residual/collateral object remains at final cancellation review. Expected: no completion/terminal claim.

## 8. Acceptance and unresolved items

Design acceptance:
- [x] Request terminality is derived from every manifest object's determinate disposition.
- [x] Ambiguous, unknown, unverified and in-flight outcomes prohibit terminalization.
- [x] COMMITTED and NOT_COMMITTED require distinct positive evidence.
- [x] Cancellation/revocation ordering and stop-future-work proof are required.
- [x] Residual/collateral boundaries and audit continuity are part of the terminal package.
- [x] Late evidence cannot silently rewrite history.

Still OPEN: exact independent verifier, authoritative mutation boundary, event ordering technology, residual discovery completeness, identity/independence model, trusted-time policy and implementation-specific stop-work proof.
