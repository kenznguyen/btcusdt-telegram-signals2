## 4. Why existing evidence is insufficient

1. EP-01's `permissions` object describes the connected actor's repository role as returned by repository metadata. It does not expose the underlying token scopes, GitHub App installation permissions, OAuth grants, credential provenance or any other effective authorization chain.
2. A GET-only request pattern is not a read-only credential boundary. The same identity may possess write/admin rights even when this particular call is read-only.
3. A generic installation listing, even if called, would not independently bind the EP-01 request to a specific installation identity or establish the exact effective permission set used for that request.
4. Reusing the existing connector for additional candidate endpoints would continue to rely on the unverified identity and would violate the fail-closed precondition in P1.8.129/P1.8.135.
5. Credential inspection, creating a restricted token/App, changing permissions, or selecting a new principal would be a different identity/authorization path and is not authorized by the current approval.

## 6. Re-entry criteria

A future inventory may resume only after all of the following are available without exposing secrets or expanding current authority:

1. A stable, independently attributable collector principal identity.
2. Non-secret evidence binding that principal to the exact request path/connector used for collection.
3. Independently verifiable effective permission evidence proving the identity is limited to the approved read-only repository scope.
4. A documented evidence timestamp, source revision/ETag or explicit unavailability, API/connector contract version, and allowlisted response digest.
5. Confirmation that the identity has no relevant write/admin capability through inherited, installation, organization, repository, workflow, runner or external-provider paths within the claimed assurance boundary.
6. Independent review of the evidence package before any EP-02–EP-08 request.

If any criterion cannot be met within the current authorization, the inventory remains PARTIAL/BLOCKED. A materially different identity or evidence path requires a new bounded proposal and explicit owner approval before use.
