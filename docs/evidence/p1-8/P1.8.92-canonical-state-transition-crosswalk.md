# P1.8.92 — Canonical State Transition Crosswalk

Date: 2026-11-09  
Closes: SR-01 (MAJOR)

## 1. Purpose and authority

This document resolves the vocabulary ambiguity between the Data Deletion Safety Contract, P1.8.82 and P1.8.86. It defines a canonical request-state crosswalk and the authority/guard requirements for transitions.

It does not collapse the independent dataset, consumer dependency, hold, copy, approval, authorization, per-object execution and evidence state domains into one global state. Each domain remains independently versioned and authoritative for its own facts.

Precedence:
1. Existing governing contracts retain their safety invariants.
2. This crosswalk is the normative mapping for deletion-request orchestration labels only.
3. Domain-specific state remains authoritative for its own facts; request state cannot manufacture a hold, release a dependency, approve a package, or prove storage disposition.
4. If a mapping or domain revision cannot be established, the request is BLOCKED/RECONCILIATION_REQUIRED; no inferred transition is allowed.

## 2. Canonical request states

| Canonical state | Meaning | Entry guard | Exit conditions |
|---|---|---|---|
| REQUESTED | Exact-scope request durably received; no eligibility conclusion | Authenticated requester; immutable request identity; exact target scope; idempotency binding | ELIGIBILITY_REVIEW, REJECTED, CANCELLED |
| ELIGIBILITY_REVIEW | Read-only review is evaluating policy, dependencies, holds, copies, recovery and evidence | Request accepted; required authoritative read boundaries available | ELIGIBLE_FOR_APPROVAL, BLOCKED, REJECTED, CANCELLED |
| ELIGIBLE_FOR_APPROVAL | All documented eligibility gates pass for the exact reviewed package; no approval implied | Complete manifest and evidence snapshot; no unknown/conflict; policy decision allows review | APPROVAL_PENDING, BLOCKED, EXPIRED, CANCELLED |
| APPROVAL_PENDING | Complete immutable approval package awaits independent decision | Eligible package digest pinned; requester/approver separation established | APPROVED, REJECTED, BLOCKED, EXPIRED, CANCELLED |
| APPROVED | Independent approver approved the exact package; no execution capability exists | Valid identity/delegation; distinct requester and approver; package digest unchanged | FINAL_RECHECK, BLOCKED, EXPIRED, CANCELLED |
| FINAL_RECHECK | Execution authority is revalidating current dependencies, holds, policy, identity, time, copies and exact object resolution | APPROVED; no cancellation/revocation; all required authoritative sources reachable | EXECUTION_AUTHORIZED, BLOCKED, EXPIRED, CANCELLED |
| EXECUTION_AUTHORIZED | Narrow authorization has been issued for exact operation/object scope and executor | Final recheck passes; authorization bound to package digest, operation, object identities/generations, executor, idempotency identity and validity conditions | EXECUTING, EXPIRED, REVOKED, CANCELLED |
| EXECUTING | One or more exact per-object operations may be in progress | Executor validates authorization and per-object mutation fence at the mutation boundary | RECONCILIATION_REQUIRED, VERIFICATION_PENDING, CANCELLED_WITH_PARTIAL_OUTCOME |
| VERIFICATION_PENDING | All authorized object operations have reported terminal backend outcomes; independent verification remains outstanding | Per-object results are durable; no in-flight or ambiguous object operation | VERIFIED_COMPLETE_WITHIN_SCOPE, RECONCILIATION_REQUIRED, NOT_VERIFIED |
| RECONCILIATION_REQUIRED | Partial, ambiguous, interrupted, conflicting or residual state requires authoritative reconciliation | Any unknown outcome, failed fence after partial work, audit discontinuity or conflicting evidence | FINAL_RECHECK only through an explicit governed resume decision; VERIFICATION_PENDING; CANCELLED_WITH_PARTIAL_OUTCOME; NOT_VERIFIED |
| VERIFIED_COMPLETE_WITHIN_SCOPE | Independent verifier confirms the exact declared scope and bounded claim | Independent oracle confirms all per-object outcomes, residual boundaries and retained evidence | Terminal |
| NOT_VERIFIED | Completion cannot be independently established or evidence is irrecoverably insufficient | Verification fails or remains unavailable after governed reconciliation | Terminal for this request; new request required for a changed/retried scope |
| BLOCKED | A required guard is unknown, unavailable, stale, conflicting or not approved | Any fail-closed guard | May return to ELIGIBILITY_REVIEW or FINAL_RECHECK only after a separately recorded resolution and fresh evidence; otherwise terminal |
| REJECTED | Request/package rejected by authorized reviewer or policy | Attributable rejection reason | Terminal; new request required |
| CANCELLED | Request cancelled before any mutation began | Durable cancellation ordered before first mutation | Terminal |
| CANCELLED_WITH_PARTIAL_OUTCOME | Cancellation/interruption after one or more object mutations | Per-object results preserved; remaining operations stopped where safely possible | Terminal only after reconciliation and verification of completed/remaining scope |
| EXPIRED | Request, approval or authorization validity ended before mutation | Trusted-time/expiry decision; no automatic execution | Terminal; new request and fresh review required |
| REVOKED | Execution authorization revoked before further mutation | Durable revocation ordered at authoritative decision boundary | If no mutation occurred, terminal; otherwise RECONCILIATION_REQUIRED |

VERIFIED_COMPLETE_WITHIN_SCOPE is intentionally bounded. It is not a global assertion that every external copy, provider backup or unmanaged recipient has been erased.

## 3. Legacy vocabulary crosswalk

| Existing label | Canonical request state | Notes |
|---|---|---|
| Proposed / Request submitted | REQUESTED | A proposal is not an eligibility result |
| Eligibility review | ELIGIBILITY_REVIEW | Read-only review only |
| Eligible for approval | ELIGIBLE_FOR_APPROVAL | Does not imply approval |
| Reviewed eligible / REVIEWED_ELIGIBLE | ELIGIBLE_FOR_APPROVAL | P1.8.82 alias; not a separate state |
| Awaiting approval | APPROVAL_PENDING | Package must be immutable |
| Approved | APPROVED | No execution authority |
| FINAL_RECHECK | FINAL_RECHECK | Preserve exact canonical label |
| Awaiting execution authorization | FINAL_RECHECK | Authorization not yet issued |
| AUTHORIZED / Execution authorized | EXECUTION_AUTHORIZED | Exact-scope capability exists; no mutation necessarily started |
| EXECUTING / Executing | EXECUTING | Per-object operations tracked independently |
| Reconciliation required / RECONCILIATION_REQUIRED | RECONCILIATION_REQUIRED | Protective, no blind retry |
| COMPLETED_PENDING_VERIFICATION | VERIFICATION_PENDING | Backend result is not independent proof |
| Verified complete / VERIFIED_COMPLETE | VERIFIED_COMPLETE_WITHIN_SCOPE | Only if independent bounded verification passes |
| Cancelled | CANCELLED or CANCELLED_WITH_PARTIAL_OUTCOME | Determined by whether any mutation began |
| Rejected | REJECTED | Terminal |
| Expired | EXPIRED | Never auto-starts work |

No legacy label may be used as an unqualified global state. Domain-specific ACTIVE, RELEASED, ARCHIVED, HELD, REVOKED or RETAINED states remain scoped to their own domain.

## 4. Transition authority and event contract

| Transition | Authorized initiator/authority | Required durable event | Required guard |
|---|---|---|---|
| REQUESTED → ELIGIBILITY_REVIEW | Lifecycle reviewer/orchestrator | ReviewStarted | Request identity and exact scope valid |
| ELIGIBILITY_REVIEW → ELIGIBLE_FOR_APPROVAL | Lifecycle reviewer | EligibilityDecisionRecorded | All eligibility evidence current and no unresolved blocker |
| ELIGIBLE_FOR_APPROVAL → APPROVAL_PENDING | Request orchestrator | ApprovalPackageSealed | Immutable package digest and distinct approver eligibility |
| APPROVAL_PENDING → APPROVED/REJECTED | Independent approver | ApprovalDecisionRecorded | Identity/delegation, package digest and separation valid |
| APPROVED → FINAL_RECHECK | Execution authority | FinalRecheckStarted | Approval current and not cancelled/revoked |
| FINAL_RECHECK → EXECUTION_AUTHORIZED | Execution authority | AuthorizationIssued | All domain revisions/fences and exact target binding valid |
| EXECUTION_AUTHORIZED → EXECUTING | Executor, after boundary validation | ExecutionStarted / ObjectMutationIntent | Authorization valid; per-object fence passes |
| EXECUTING → VERIFICATION_PENDING | Executor reports all object outcomes | BackendOutcomesSealed | No in-flight or ambiguous object operation |
| Any in-flight state → RECONCILIATION_REQUIRED | Any trusted observer/orchestrator | ReconciliationRequired | Ambiguous/partial/conflicting outcome |
| VERIFICATION_PENDING → VERIFIED_COMPLETE_WITHIN_SCOPE | Independent verifier | VerificationAttested | Independent oracle and bounded claim pass |
| Pre-mutation state → CANCELLED/EXPIRED/REVOKED | Authorized actor/authority | TerminalDecisionRecorded | Durable ordering proves no mutation began |
| EXECUTING → CANCELLED_WITH_PARTIAL_OUTCOME | Executor/orchestrator at safe boundary | PartialCancellationRecorded | Completed and remaining objects enumerated |

A service account may perform a narrowly delegated technical action, but it does not become an independent human approver. A requester cannot approve its own request. Executor cannot approve, issue authorization or independently verify its own work.

## 5. Domain-state separation

The request state is an orchestration summary. The following domain states must be independently pinned and checked:

- Dataset lifecycle: exact dataset/version lifecycle revision.
- Consumer dependency: each dependency ID, owner, version and authoritative revision.
- Hold: hold IDs, scope, state and authoritative hold revision.
- Copy lifecycle: each copy identity, lineage, recovery role and disposition revision.
- Approval package: immutable digest and decision.
- Execution authorization: exact operation, executor, object list/generations, idempotency identity and validity.
- Per-object execution: independent intent, outcome and reconciliation status.
- Evidence lifecycle: audit continuity, provenance and verifier result.

No transition in one domain implies a transition in another. In particular:
- ACK does not release a dependency.
- APPROVED does not imply EXECUTION_AUTHORIZED.
- EXECUTION_AUTHORIZED does not imply EXECUTING.
- A backend success does not imply VERIFIED_COMPLETE_WITHIN_SCOPE.
- A copy's archive/deletion state does not change source or sibling-copy state.
- Request cancellation does not reverse a completed mutation.

## 6. Terminality, re-entry and invalidation

1. REJECTED, CANCELLED, EXPIRED and VERIFIED_COMPLETE_WITHIN_SCOPE are terminal for the exact request identity.
2. A changed manifest, policy revision, object generation, material dependency/hold/copy revision or operation invalidates the affected approval/authorization and requires a new final review; if scope changes, a new request is required.
3. RECONCILIATION_REQUIRED cannot return to EXECUTING through a blind retry. A governed resume must establish each object's actual state, preserve completed outcomes and issue fresh authorization if required.
4. NOT_VERIFIED is not success and cannot be relabelled complete by the executor.
5. A request blocked by unknown state may be re-evaluated only after authoritative evidence resolves the unknown and the evidence is refreshed under an approved freshness policy. No numeric freshness value is defined here.
6. No automatic transition is driven by TTL, age, heartbeat absence, review date or elapsed grace.

## 7. Ordering and consistency requirements

Every state transition must be attributable to a unique event identity, actor, request ID, prior revision, resulting revision, trusted ordering evidence and package/domain revision references.

If event ordering, revision continuity, authority, trusted time or audit durability is unknown, the transition is BLOCKED/CONFLICTED. Local wall-clock ordering or a stale read model cannot establish authority.

The mutation-boundary protocol is specified separately in P1.8.93. This crosswalk does not claim that any transaction, registry, lock, token or storage fence has been implemented.
