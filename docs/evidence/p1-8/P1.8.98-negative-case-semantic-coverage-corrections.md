## 3. Added deterministic vector requirements

### NEG-REC-03 — Missing or ambiguous recovery-chain member

Initial fixture: a recovery-point manifest references a base, incremental, log, metadata or key dependency that is missing, duplicated with conflicting identity, or cannot be bound to the exact recovery point.

Deterministic sequence:
1. Seal a synthetic recovery-point manifest and its exact member identities.
2. Remove or corrupt one required member reference, or present two conflicting identities for one chain position.
3. Run read-only eligibility evaluation.
4. Assert that the affected recovery point is UNKNOWN/CONFLICTED and dependent disposition remains BLOCKED.

Independent oracle: separately held immutable fixture manifest and object inventory. Expected: no chain-completeness claim and no disposition authorization. This vector is distinct from NEG-ADP-07, which tests removal that invalidates another recovery point.

### NEG-T3-02 — Unresolved ledger-specific lineage or obligation

Initial fixture: synthetic CORE_LEDGER and AI_LEDGER are separate namespaces with distinct immutable identities and obligations.

Deterministic sequence:
1. Introduce an unresolved order, reservation, risk, funding, audit, event-history or downstream dependency for one ledger.
2. Ensure the other ledger has a distinct and independently resolved state.
3. Evaluate disposition for each exact ledger scope.
4. Assert that the affected ledger remains BLOCKED and the unrelated ledger's evidence is not substituted.

Independent oracle: separately controlled ledger fixture inventory and obligation map. Expected: preserve CORE_LEDGER/AI_LEDGER separation; no inference from strategy inactivity, report/cache expiry or the other ledger's state. This vector is distinct from NEG-T3-01, which tests direct conflation of both ledgers in one scope.

### NEG-EVD-06 — Missing or dangling evidence reference

Initial fixture: a decision package requires a specific evidence reference, but the reference is absent, dangling, or cannot be resolved to an immutable evidence object and declared scope.

Deterministic sequence:
1. Seal a synthetic package listing the required evidence ID and digest.
2. Remove the reference target or make the reference unresolved while leaving the package unchanged.
3. Execute read-only package validation.
4. Assert BLOCKED/NOT_VERIFIED and preserve the unresolved obligation.

Independent oracle: separately stored expected evidence manifest and namespace inventory. Expected: missing reference is not interpreted as proof that no hold, dependency, recovery or audit obligation exists.

### NEG-EVD-07 — Evidence provenance/source/scope cannot be resolved

Initial fixture: an evidence object exists and may have a valid local digest, but its claimed source, version, issuer/signer or declared scope cannot be independently resolved.

Deterministic sequence:
1. Provide an evidence object with a claimed source/version/scope.
2. Remove or conflict the authoritative source mapping, issuer identity or scope binding.
3. Validate the evidence using an independent provenance oracle.
4. Assert evidence rejection and protective BLOCKED/NOT_VERIFIED state.

Independent oracle: separately controlled source-of-truth identity and provenance fixture. Expected: object existence or self-consistent digest alone does not establish authenticity, authority or applicability.

### NEG-ADP-10 — Unexplained residual reference/index/sidecar

Initial fixture: a synthetic adapter reports an exact object disposition, while a separate residual inventory contains an unexplained secondary index, reference, tombstone, sidecar or materialized pointer.

Deterministic sequence:
1. Record exact manifest and expected object generations.
2. Have the synthetic adapter report its bounded object outcome.
3. Expose an additional residual reference through a separately controlled read-only oracle.
4. Assert PARTIAL/NOT_VERIFIED and block any completion claim until the residual is classified and reconciled.

Independent oracle: read-only inventory not sourced from the executor's mutable result channel. Expected: adapter success cannot erase an unexplained residual or widen its own bounded claim.

## 4. Semantic distinction from existing vectors

- NEG-REC-03 tests chain-member identity/completeness uncertainty; NEG-ADP-07 tests an operation that invalidates another recovery point.
- NEG-T3-02 tests unresolved ledger-specific obligations; NEG-T3-01 tests combining two distinct ledgers into one scope.
- NEG-EVD-06 tests missing/dangling references; NEG-EVD-07 tests unresolved provenance/source/scope. NEG-EVD-02 remains digest/signature tampering or provenance mismatch where a concrete mismatch is observable.
- NEG-ADP-10 tests unexplained residual references/indexes/sidecars; NEG-ADP-03–06 remain specific version, WAL/journal, replica/backup and delayed provider residual cases.

No existing vector is reinterpreted as proving a condition it does not directly exercise.

## 5. Determinism and oracle requirements

Every new vector must use:
- immutable synthetic namespace and proof of isolation;
- exact fixture manifest and source/test-spec SHA;
- deterministic barrier/event schedule where concurrency is relevant;
- exact object identities, versions and expected affected set;
- a read-only independent oracle outside the executor trust boundary;
- explicit expected state and no-side-effect assertions;
- durable redacted observations and artifact provenance if a future run is separately approved.

No sleep-based race assertion. If the oracle cannot establish the exact state, report NOT_VERIFIED or NOT_TESTABLE, never PASS.
