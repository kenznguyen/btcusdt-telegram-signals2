# P5.4.83 — Android T0-B Read-Only Preflight Checklist

**Date:** 2026-11-04 (Asia/Ho_Chi_Minh)  
**Status:** DOCUMENTATION / CHECKLIST ONLY — NOT EXECUTED  
**Workstream:** P1 Centralized Data Feeder, Android-first  
**Branch:** `feature/p5-4-1-post-merge-validation-20261103`

## 1. Purpose

Define the evidence and safety gates for T0-B on the owner-selected Android canonical host. This checklist does not probe a device, resolve a live filesystem path, open SQLite, create a database, start a service, connect an exchange or synchronize market data.

## 2. Governing architecture

- Android-hosted SQLite is the canonical T0 store.
- Market Data and Paper Ledger share one physical SQLite file.
- ADR-002 designates the existing `regular` Android variant as the sole canonical host; the separately installed `.paper` variant is an authenticated IPC client only.
- The host alone is intended to own canonical path resolution, database identity, schema/migration authority, transactions, lease/fencing, recovery/readiness, Market Data, Paper Ledger, audit, Shared Risk Engine and Kill Switch.
- The client must not receive a database path, file descriptor, SQLite handle, SQL, lease token or writer credential; no client shadow database or fallback writer.
- PC is optional research/backtest/AI compute and a read-only consumer, not the T0 canonical writer.
- GitHub Actions runs isolated fixture/static CI. It is not an Android runtime host.

## 3. Source-level prerequisites — perform before device access

| Check | Required evidence | Current status |
|---|---|---|
| Canonical host identity | Gradle application ID/variant and ADR-002 match | Source direction known; installed package identity NOT VERIFIED |
| Host composition root | One application-scoped CanonicalRuntime owns storage and writer capabilities | NOT IMPLEMENTED / NOT VERIFIED |
| Canonical path authority | Explicit host-owned resolver returns one app-private path and stable opaque DB identity | NOT FOUND in P5.4.65 source review |
| Shared DB topology | Market Data and Paper Ledger use the same physical DB and transaction coordinator | Owner-approved architecture; source implementation NOT FOUND |
| Migration authority | Explicit SQLite migration registry and read-only verifier | Architecture approved; Android implementation NOT FOUND |
| Feeder composition | Android host composes scheduler/recovery through existing sync/Gateway semantics and same-file lease/fencing | NOT FOUND in reviewed Android source |
| Client isolation | `.paper` has no DB open/create/write, shadow DB, lease or fallback path | ADR-002 requirement; implementation NOT VERIFIED |
| IPC security | Bound Service + typed Binder/AIDL, signature permission, per-call UID/package/signer checks | ADR-002 requirement; implementation NOT FOUND in P5.4.65 review |
| Risk/ledger boundary | Core and independent AI intents reach the same host Shared Risk Engine/Kill Switch before paper-ledger mutation | Approved architecture; implementation NOT FOUND |

**Stop condition:** if the canonical host/path resolver or sole-writer composition is absent, T0-B cannot truthfully identify a canonical Android DB path. Do not substitute a guessed `filesDir`, Termux path, SharedPreferences file, remote API or PC path.

## 4. Device preflight — requires separate explicit Android access approval

After all source-level prerequisites pass and the owner separately authorizes narrowly scoped device access:

1. Record device model, Android/API level, installed host package/version, source SHA/build provenance and installed signer identity.
2. Resolve the database path only through the approved host-owned path authority. Do not scan unrelated storage or infer a path from package naming.
3. Record canonicalized path, app-private root containment, file existence/type, owner/access metadata and stable opaque DB identity without opening SQLite.
4. Record the presence/absence and metadata of the corresponding `-wal` and `-shm` files without copying, deleting, truncating or opening them.
5. Confirm the `.paper` client has no independent canonical DB path or writer capability through source/configuration evidence; do not attempt a write.
6. Capture a read-only evidence bundle with timestamp, app/source identity, path-authority output, file metadata and exact tool/device provenance.

This phase is path/identity metadata inspection only. Opening SQLite, running `PRAGMA`, integrity checks, migration inspection or reading rows requires a separate explicit authorization. Creating/modifying the DB is not part of T0-B.

## 5. Fail-closed outcomes

- Missing host/path authority, unknown package/signer, path outside host app-private storage, ambiguous DB identity, separate Market Data/Paper Ledger files, unproven same-file lease fencing or unexpected client DB => **BLOCKED**.
- Missing DB is reported as missing; never auto-create it.
- Unknown WAL/SHM state is **NOT VERIFIED**; never manipulate sidecar files to make the check pass.
- Any need to open or mutate SQLite exits this checklist and requires separate approval.
- A successful metadata preflight does not prove schema correctness, runtime readiness, Feeder operation, candle freshness or recoverability.

- No Android device/filesystem access or APK install/build.
- No canonical DB open/create/write, SQLite query, migration, integrity check or sidecar manipulation.
- No Feeder startup, lease acquisition, exchange connection or market-data synchronization.
- No production backup/restore, Recovery Latch/Kill Switch mutation or writer activation.
- No PC/VPS/Codemagic runtime; no live orders. Keep `AI_EXECUTION_ENABLED=false`.
