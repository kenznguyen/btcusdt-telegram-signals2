- Native fixed-query reader now reads all `canonical_database_identity` rows and all `schema_migrations` rows after the DEFERRED snapshot anchor and on the same registered `sqlite3*` handle as runtime/schema/D5 queries.
- Each result set validates exact column names/types through the existing fixed-query runner; row and payload bounds remain enforced.
- Native Debug in-memory JNI fixture and host C++ :memory: fixture now include one identity row and one bootstrap migration row.
- Kotlin wire decoder parses typed identity and applied-migration rows and rejects malformed/truncated/trailing payloads using the existing strict framing rules.
- JNI decoder binds the decoded evidence to the currently held native handle token (`native-handle:<handle>`).
- Added pure `CanonicalReadSnapshotAssembler`. It requires a successful native reply, nonblank adapter token, exactly one identity row, ACTIVE parsed pin, matching role/instance, valid provenance/format, migration owner-domain alignment, and a complete migration verification. It computes observed D5 SHA-256 from the decoded envelope itself; caller cannot supply observed digest or consistency enum.
- The assembler emits a snapshot only when the existing snapshot verifier returns VERIFIED; all failure paths return no snapshot.
- Added JVM tests for successful assembly, pending pin, duplicate identity rows, pin mismatch, migration checksum mismatch, digest mismatch and non-verified native reply.
- Updated wire decoder and native fixture parity tests for v2 identity/migration sections.
