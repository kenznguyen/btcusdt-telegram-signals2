## 3. Existing implementation seams

### 3.1 Suitable for fixture-only harness

- Reuse the existing Python `unittest` and `tempfile.TemporaryDirectory` style.
- Keep new tests in a dedicated module, e.g. `tests/backup_restore/` or another repository-approved test package after checking current discovery conventions.
- Build fixture DBs explicitly from schema contracts; never point tests at runtime environment defaults.
- Keep fixture seeding and expected-state generation separate. Expected-state JSON must come from deterministic seed inputs, not from reading the backup being tested.
- Use Python SQLite Online Backup API for snapshot tests. A test helper should accept explicit source/destination connection objects or paths under a validated temp root, not a global DB path.
- A read-only verifier should use SQLite URI `mode=ro`; it must not instantiate `PaperLedger` or call schema initialization/default-state helpers.
- Test single-file SQLite first. Split-store fixtures require a shared snapshot epoch and barrier metadata; they must not claim database-level atomicity.

### 3.2 Not yet safe to implement as an operational utility

- There is no approved canonical path or approved host.
- The runtime may select PostgreSQL for market data while the Paper Ledger remains SQLite-backed. No existing single operation proves an atomic snapshot across both.
- The current lease generation is persisted in SQLite; no approved non-rollback monotonic restore-epoch authority has been selected.
- The Kill Switch is persisted in the database; no approved external recovery latch/approval authority has been specified.
- Risk policy is partly external configuration. The authoritative sanitized config fingerprint and its schema are not yet defined.
- Backup destination, encryption/key custody, retention and RPO/RTO are open.
- Therefore no production backup scheduler, restore command, promotion path or automatic restart gate should be added yet.

## 5. Proposed module boundaries

Keep production behavior and test machinery separate:

- `fixture_factory`: creates temporary schema/seed data; no production path resolution.
- `snapshot_adapter`: fixture-only wrapper around SQLite Online Backup API.
- `manifest_model`: validates versioned metadata and required fields; no secret material.
- `readonly_verifier`: read-only DB connection and deterministic domain projections.
- `failure_injection`: truncation, byte mutation, interrupted staging and missing-state fixtures.
- `test_evidence`: machine-readable result, sanitized environment audit and checksums.

These are proposed logical boundaries, not approved filenames or an instruction to create them. Avoid a generic backup framework, pluggable storage abstraction, scheduler, retention engine or cross-platform service until actual approved requirements demand them.
