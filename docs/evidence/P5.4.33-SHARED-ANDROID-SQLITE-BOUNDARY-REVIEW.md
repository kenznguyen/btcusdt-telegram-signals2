## Findings

### F1 — Feeder internal SQLite identity
- `build_production_runtime()` reads `MARKET_DATA_DB` and `T0_FEEDER_LEASE_DB`; an omitted lease path defaults to the candle path.
- It rejects lexically distinct paths unless their expanded/resolved paths identify the same file.
- The production factory constructs SQLite CandleStore, T0WriteGateway, LeaseStore and FeederRuntimeStatusStore using that same resolved target.
- This is an internal T0 composition invariant only; it does not establish Paper Ledger identity or the actual Android path.

### F2 — Paper Ledger remains independently path-configured
- `PaperLedger.__init__(db_path)` accepts a standalone path, creates its parent directory, opens SQLite, enables WAL and creates/ensures Paper Ledger tables.
- No shared canonical-path resolver or cross-component identity assertion is present in the inspected PaperLedger constructor.
- The constructor can therefore be pointed at a different SQLite file from `MARKET_DATA_DB`; the source inspected here does not prevent that configuration.

### F3 — No shared composition root established in inspected files
- `app.py` imports Feeder health/status components but does not import or compose `PaperLedger`.
- `build_production_runtime()` composes T0 components only and does not receive or construct PaperLedger.
- `paper_execution/test_ledger.py` uses its own temporary `shared.sqlite3` fixture path and tests ledger behavior, not identity with the Feeder's path.
- This bounded source set does not establish where an Android application-level composition root should own the single canonical path. It is not proof that no other integration exists outside the inspected files.

### F4 — CI intentionally prevents canonical paths
- G2 integration GREEN workflow clears `MARKET_DATA_DB`, `T0_FEEDER_LEASE_DB`, `PAPER_DB` and `PAPER_TRADING_DB` and runs isolated tests.
- This is appropriate for fixture-only CI; it does not validate Android path wiring or production composition.
