## Owner decision

**ACCEPTED: Option B — Dedicated canonical host package plus authenticated IPC client.**

The owner selected Option B from the three choices presented in P5.4.38:
- A — same application ID for local variants;
- B — one dedicated canonical host package plus authenticated IPC client;
- C — keep the separate `.paper` package remote-API-only.

This decision selects the package ownership/access model. It does not select exact package IDs or the concrete IPC mechanism.

## Binding architecture constraints

1. One designated Android host package/process owns the one physical canonical SQLite file used by T0 Market Data and Paper Ledger.
2. The host alone owns canonical path authority, DB identity, schema/migration authority, transaction coordinator, lease/fencing, recovery/readiness checks and canonical writer capability.
3. The separately installed `.paper` package is an IPC client, not a DB owner or writer.
4. The client receives no raw DB path, SQLite handle, file descriptor, arbitrary SQL capability, writer credential or lease authority.
5. The host authenticates and authorizes callers using verified Android caller identity and trusted signing-certificate/package policy. Use signature-level permissions where appropriate to the selected IPC mechanism.
6. IPC exposes typed domain commands and read-only projections only. Mutations are revalidated host-side for readiness, fencing, recovery state, idempotency and Kill Switch.
7. Core and independent AI signal sources remain distinct, but all Paper intents pass through the same host-side Shared Risk Engine/Kill Switch and Paper Ledger boundary.
8. Host unavailable, unauthorized caller, incompatible contract, stale owner/fencing or uncertain state means fail closed. No local shadow DB or implicit fallback writer.
9. PC remains read-only research/backtest consumer.
10. Paper-only remains in force; `AI_EXECUTION_ENABLED=false`.
