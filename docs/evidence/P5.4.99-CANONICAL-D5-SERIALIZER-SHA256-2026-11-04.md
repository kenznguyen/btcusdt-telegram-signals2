## Implementation

Added `android-app/app/src/main/java/com/kenznguyen/btclivealerts/CanonicalD5Serializer.kt`.

The source-only API includes:
- `D5RuntimeIdentity`;
- catalog, table_xinfo, index_list, index_xinfo and foreign_key_list record models;
- `D5SchemaEnvelope`;
- `CanonicalD5Serializer.serialize()`, `sha256()` and `sha256Hex()`.

Canonical binary format v1:
- four-byte magic `D5SC`;
- 32-bit big-endian format version;
- runtime identity fields in fixed order;
- each section tagged by its fixed name and prefixed with a 32-bit row count;
- signed 32-bit big-endian integers;
- exact UTF-8 strings prefixed by a 32-bit byte length;
- nullable strings encoded as length `-1`; empty strings encode length `0`;
- booleans encoded as one byte (`0` or `1`);
- catalog rows sorted by UTF-8 byte order of schema/type/name/table name;
- table columns sorted by schema/table/cid;
- indexes sorted by schema/table/sequence/name;
- index columns sorted by schema/table/index/sequence;
- foreign keys sorted by schema/table/id/sequence;
- duplicate logical identities and invalid runtime identity fail closed;
- SQL text is not trimmed, normalized, case-folded or Unicode-normalized;
- SHA-256 is lowercase 64-character hexadecimal.

No production dependency or runtime wiring changed. The serializer does not read SQLite and does not prove that source records came from a consistent transaction.
