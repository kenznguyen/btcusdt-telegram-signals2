## Composition and runtime observations

### A. No Android database composition root is visible in the reviewed entrypoints
- No custom Application subclass or dependency injection container is declared in the reviewed manifest/build configuration.
- `MainActivity` is the visible UI entrypoint; it directly selects the UI shell.
- The regular variant starts `StrategyMonitorService` from `onResume()`; the parallel variant skips that service and mounts the paper dashboard.
- `StrategyMonitorService` constructs its market/strategy/scanner objects locally using lazy fields rather than receiving a canonical database/path authority.
- No reviewed entrypoint constructs an Android SQLite connection, migration coordinator, CandleStore, T0WriteGateway, LeaseStore, PaperLedger, Risk repository or shared transaction coordinator.

### B. Existing local persistence is not canonical storage
- `StrategyMonitorService` reads/writes `SharedPreferences("strategy_state_v1")` for strategy state/cursor, monitor status, alert queue/dedupe, scanner state and order-book snapshots.
- `CompleteDashboard` and `FiveLayerPanel` also use the same preference namespace for UI/configuration state; FiveLayerPanel persists only the API URL from the connection configuration.
- FiveLayerPanel deliberately holds read/control tokens and server readings in Compose memory, not SharedPreferences.
- `PaperOrderHistory` is a display surface for server-provided snapshots. The README says both Android variants can share the same **server-side** paper ledger when configured with the same API.
- Therefore current Android local preferences, Compose state and remote Paper API must not be misclassified as the intended shared Android canonical SQLite database.

### C. Path authority candidates and gaps
No canonical DB path authority exists in the reviewed sources. A future composition root could be introduced at the application/process boundary, but its exact class and location are not selected by this source trace.

Required missing interfaces:
1. Application-scoped canonical database identity/path provider.
2. Explicit schema provisioner and migration coordinator.
3. Injected shared SQLite transaction/connection boundary.
4. Android T0 CandleStore and fenced write gateway.
5. Android LeaseStore/runtime readiness and recovery-epoch authority.
6. Paper Ledger, order/audit, Risk/Kill Switch and equity repositories backed by the same selected DB identity.
7. Read-only UI and PC export/query interfaces.
8. Service startup gating that refuses canonical writes unless DB identity, schema, fencing, recovery state and Kill Switch are verified.

The source trace does not choose the Android filename/path, migration framework, database connection API or exact service ownership model.

## Important variant boundary
- The normal app variant starts the Chart Pro StrategyMonitorService and uses its own app-private preferences.
- The parallel `applicationIdSuffix=".paper"` variant opens FiveLayerStandaloneDashboard and does not start that local monitor service.
- The parallel app reads/writes the remote paper backend through HTTPS. Separate Android app storage does not create a separate server ledger.
- This behavior is not an implementation of Android-local T0 + Paper Ledger shared SQLite.
