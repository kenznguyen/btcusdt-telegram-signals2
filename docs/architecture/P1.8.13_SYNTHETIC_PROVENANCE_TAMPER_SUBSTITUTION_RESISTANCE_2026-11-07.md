## Limits and interpretation

- SHA-256 provides integrity comparison only; it is not a digital signature, trusted timestamp, or authenticated identity.
- The expected artifact digest must be obtained from a trusted external record (here, GitHub Actions artifact metadata/report). If an attacker can replace both the provenance record and the trusted expected digest, this mechanism alone cannot establish authenticity.
- A/B fixtures generated with the same deterministic seed are byte-identical; swapping those exact equal payloads is observationally indistinguishable. The independent negative unit test uses distinct A/B descriptor contents with the same source SHA to prove descriptor-label substitution is rejected.
- No Root B/provider independence, real production source authenticity, production DB/WAL durability, real power-loss recovery, or production runtime certification is claimed.
