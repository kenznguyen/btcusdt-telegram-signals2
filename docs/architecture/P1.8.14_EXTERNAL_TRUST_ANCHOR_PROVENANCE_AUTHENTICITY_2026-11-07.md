## Security interpretation and limits

- The trust anchor is the Sigstore certificate and verified Rekor transparency-log evidence, not a hash stored beside the artifact.
- The attestation proves that the identified GitHub Actions workflow, under the recorded repository/source identity, attested to this exact archive digest. It does not prove that the source code or generated market data is correct or safe.
- Workflow maintainers with permission to change the workflow can still change what it builds or attests. This is not an independently governed trusted-builder/release process or a multi-party approval policy.
- The SLSA predicate contains workflow-supplied claims; trust decisions rely on the cryptographically verified certificate identity and timestamp, plus explicit CLI policy flags, rather than treating arbitrary predicate text as independently authenticated.
- The Sigstore bundle is retained for later verification. Air-gapped/offline verification requires a separately obtained and trusted Sigstore trusted-root bundle; this workflow's acceptance verification was online using GitHub CLI and the retained attestation bundle.
- This does not certify Root B/provider independence, production source correctness, database/WAL durability, real power-loss recovery, or runtime execution safety.
