Behavior:
1. GitHub CLI obtains the Sigstore trusted-root snapshot using `gh attestation trusted-root`.
2. The workflow validates the JSONL framing and verifies the exact root bytes against the reviewed SHA-256 pin before signing the evidence archive.
3. The archive includes `trusted_root.jsonl`, its SHA-256 sidecar, the source-pinned trust-root module and the reusable offline verifier.
4. GitHub Artifact Attestations signs the archive with SLSA Build Provenance.
5. A separate GitHub-hosted runner downloads the artifact and checks the subject archive digest.
6. The runner extracts the trusted root and verifies its bytes against the pin from the exact checked-out source.
7. The runner invokes `verify_offline.sh` inside `sudo unshare --net`, a Linux network namespace without external network connectivity. The command uses only the local artifact, local Sigstore bundle and local custom trusted root.
8. Verification constrains repository, signer workflow, source commit, source ref, GitHub OIDC issuer and denies self-hosted runners.
9. The independent runner validates the CLI verification result against the expected archive SHA-256, SLSA predicate, signing certificate and verified timestamp.

The helper compares the raw trusted-root digest with the expected pin before parsing the JSONL, so modified bytes are rejected before they are interpreted.

## Security interpretation and limits

- The trusted-root SHA pin detects changes to the exact trusted-root snapshot. SHA-256 is an integrity pin, not a signature or independent identity proof by itself.
- Authenticity of the root snapshot depends on the GitHub CLI/TUF trusted acquisition path and independent review of the pin update.
- Offline verification proves the supplied artifact and bundle against the pinned trust material and the recorded signer/source identity. It cannot learn about later revocations or root rotations while disconnected.
- The pinned root may become stale when Sigstore trust material rotates. Offline verification of later signatures may fail until the root is refreshed through a separately reviewed update.
- Offline `--repo` identity comparison relies on repository identity recorded in the signing certificate; GitHub documents that offline bundle verification cannot detect later repository renames or name reuse. Preserve the source repository ID and independently check it when importing evidence.
- This does not prove market-data correctness, Root B/provider independence, production DB/WAL durability, real power-loss recovery, or runtime execution safety.
