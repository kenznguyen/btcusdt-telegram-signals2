## Approval and scope

User approval: `APPROVE P1.8.7`.

Implemented an isolated synthetic reference journal using POSIX `flock`, a same-directory temporary file, file `fsync`, atomic `os.replace`, and parent-directory `fsync`. Each admission reloads and validates the journal while holding the process-shared file lock, applies the shared risk gate, and persists the resulting decision before releasing the lock.

Contracts:
- Independent processes cannot over-reserve total exposure.
- Independent processes cannot exceed the configured open-position cap.
- Two crash injection points model process termination before atomic replace and immediately after atomic replace.
- Crash before replace preserves the old complete state; retry can then commit once.
- Crash after replace observes the complete committed state; replay of the same intent is idempotent.
- Truncated/corrupt state is rejected, not silently reset.
- Missing state after initialization is rejected; explicit initialization is required.

Fault injection uses child-process `os._exit` and is confined to this synthetic test implementation.

## Verdict and strict limitations

**P1.8.7: PASS for the synthetic POSIX local-filesystem reference model and exact-source CI contracts only.**

This tests cooperating processes on one local Linux filesystem with POSIX advisory locks. It does not prove:
- distributed/multi-host locking or network filesystem semantics;
- behavior under actual power loss, kernel panic, storage-controller cache loss, or filesystem corruption;
- durability guarantees on filesystems/mount options other than the CI runner;
- production database transactions, WAL recovery, backup/restore, or service-level availability;
- cryptographic authenticity of the snapshot checksum (SHA-256 is integrity detection, not a signature).

The crash tests terminate child processes at deterministic file-replacement boundaries. They are not real machine power-failure tests.
